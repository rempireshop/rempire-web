# Одна таблица тарифов — план

Ренат: «I just need to control the shipping price for the client in the checkout
according to Montonio price. If I do not like the Montonio price, I will just
override it… it seems to me that this delivery is a bit over engineered.»

Три таблицы на экране («Пакомат»/«Курьер»/«Бесплатно от» + фолд «Перевозчики и
наценка» + кнопка «Заполнить по тарифам Montonio») превращаются в одну.

---

## 1. Что читает цену сегодня (проверено в коде)

`quoteFromRules()` (src/lib/shipping.ts:539) берёт первое, что нашлось:

```
carriers[carrier][country] → carriers[carrier][zone] → carriers[carrier].default
  → carrierPrice(carrier, country)      // тариф Montonio за этого перевозчика
  → methods[m][country] → methods[m][zone] → methods[m].default → 0
```

`carrierPrice()` ненулевой **только** для EE/LV/LT/FI и только для перевозчика,
у которого есть тариф в `src/data/montonio-tariffs.json` (omniva, smartpost,
dpd, unisend — у Venipak тарифа нет нигде).

Следствия, которые и определяют план:

* колонка «Пакомат» (`methods.parcel`) доходит до покупателя только там, где у
  перевозчика нет тарифа (Venipak) или где перевозчика вообще нет;
* «Наценка» доходит до цены ровно одним путём — `carrierPrice(..., rules.markup)`
  в пустой ячейке перевозчика. На этом магазине пустых ячеек нет: `parse`
  подмешивает `carrierPriceTable()` в `carriers` до чтения строки, так что
  ячейка всегда заполнена. То есть наценка сегодня не меняет ни одного счёта;
* подсказка под полем берёт **живые** тарифы (`/api/admin/shipping/rates/`), а
  касса и запрет сохранения — офлайн-зеркало. Два разных числа.

Снимок цен «до» (216 сочетаний страна × способ × перевозчик) снят с кода и
заморожен в `tests/shipping-rate-table.test.ts`. Дефолты и реальная строка
настроек (миграции 030 → 031 → 148 → 149) дают **одинаковые 216 цен**.

## 2. Что становится хранимой формой

`settings.shipping_rules` — **та же форма минус `markup`**:

```jsonc
{
  "freeFrom": 59,
  "freeFromByCountry": { "EU": 200 },
  "methods": {
    "parcel":  { … },   // больше не редактируется: запасная цена
    "courier": { … },   // колонка «Курьер»
    "pickup":  { "default": 0 }
  },
  "carriers": { "omniva": { "EE": 3.19, … }, … },   // колонки перевозчиков
  "countriesOff": ["CH", "CY", …]
}
```

* `markup` **убирается** из типа, из дефолтов и из `parseShippingRules()`.
  Старая строка с этим ключом читается как раньше — ключ просто игнорируется.
* `methods.parcel` **остаётся и honoured**, но уходит с экрана. Это
  сознательный выбор, а не миграция: удалить его — значит поменять цену
  Venipak-пакомата (EE 5,47 €) и любого заказа, пришедшего со способом,
  который `normalizeMethod()` свёл к «parcel» без перевозчика. Миграции нет
  вообще: магазин, который не открывал новый экран, платит ровно то же.

## 3. Правило ячейки: пусто = Montonio, число = ваше

Уже так для ячеек перевозчиков. Достраивается до курьера:

```
methods.courier[country] → courierPrice(country) → methods.courier[zone] → default
```

`courierPrice(country)` = `customerPrice(costBasis(country,"courier").price)` —
тот же расчёт, что уже строит `countryPriceTable().courier`. Ни одна цена
сегодня не двигается: в дефолтах и в строке настроек ячейка курьера заполнена
для всех 25 стран, так что новый шаг недостижим, пока владелец сам не очистит
поле — а это и есть то, что он попросил.

Наценка выкидывается и из `carrierPrice()` в `quoteFromRules()`. Единственный
путь, где она могла бы сработать, — пустая ячейка перевозчика; на этом магазине
таких нет (см. §1), поэтому ни один счёт не меняется.

## 4. Что уходит

| Уходит | Почему |
|---|---|
| Колонка «Пакомат» | доходит до покупателя только через Venipak; `methods.parcel` остаётся в данных |
| Поля «Наценка, %» / «Наценка, €» | не меняли ни одного счёта |
| Кнопка «Заполнить по тарифам Montonio» + «Разрешить снижать текущие цены» | её работа — вписать числа, которые теперь и так по умолчанию |
| Фолд «Перевозчики и наценка» | перевозчики стали колонками |
| `suggestShippingRulesFromTariffs()`, `applyMarkup()`, `ShippingMarkup` | серверная половина той же кнопки |
| Живой запрос тарифов на этом экране | см. §6 |

Появляется: «Везде взять цены Montonio» — очищает все переопределения разом
(только черновик, до «Сохранить» магазин не трогается). «Вернуть значения по
умолчанию» остаётся рядом: это другая кнопка — она возвращает и 10,84 €, и
список выключенных стран.

## 5. Экран

Сетка `.adm-rates`, семь колонок:

```
Страна | Omniva | SmartPosti | DPD | Unisend | Курьер | Бесплатно от
```

Ячейка перевозчика существует ровно там, где у Montonio есть тариф
(`carrierPriceTable()`): Omniva EE/LV/LT, SmartPosti EE/LV/LT/FI, DPD
EE/LV/LT/FI, Unisend EE/LV/LT. Остальное — «—». Это в точности та таблица,
которую он утвердил.

**«—» против пустого поля.** «—» — не поле, а текст: серый прочерк и подпись
«не возит». Пустое поле — настоящий `<input>` с белым фоном и подписью-ценой
под ним. Они отличаются структурой, а не только цветом.

**Под каждым полем — одно число:** цена, которую магазин возьмёт, если поле
пустое. Пусто → это же число написано серым («Montonio 3,19 €»). Число вписано
→ подпись становится кнопкой «Montonio 3,19 € · вернуть» (сброс одной ячейки,
44 px высоты вместе с полем над ней).

**Телефон 375 px.** Семь колонок не влезут, и горизонтальная прокрутка
внутри панели уже показала себя плохо (затенение у края всё равно что-то
прячет). Поэтому на телефоне таблица не сжимается, а **разворачивается**: одна
строка = одна карточка страны, колонки становятся подписанными полями по два в
ряд — та самая форма, которую `.adm-tariffs` уже применяет на телефоне
(`.adm-tariffs__l` рисует имя колонки над полем). Эстония — шесть полей
(4 перевозчика + курьер + бесплатно от), Финляндия — шесть (два перевозчика,
два прочерка, курьер, порог), «Другие страны Европы» и «Остальные страны» — два.
Никакой горизонтальной прокрутки, каждое поле 44 px, подпись колонки всегда
видна.

**Остальные страны Европы.** Фолд «Цены по странам Европы» остаётся — он и был
правильной идеей: шесть строк читаются с одного взгляда, двадцать семь нет. Но
внутри фолда таблица своя, в три колонки (Страна | Курьер | Бесплатно от):
пакоматов там нет ни у одной страны, и двадцать один ряд из четырёх прочерков —
это шум. Над фолдом одна строка: «В этих странах пакоматов нет — только
курьер». Греция, Венгрия и Румыния — курьер есть, пакомата нет; у них в колонке
курьера обычное поле. Блок «Куда Montonio не возит» остаётся как был.

## 6. Два дефекта

1. **`fetchMontonioRates` принимает 0 как цену** (`price < 0` — единственный
   отказ). Montonio отдаёт 0 за курьера DPD в Эстонии. Нуль там значит «этот
   маршрут не тарифицирован для этого магазина», а не «доставка бесплатна»:
   курьер, который ничего не стоит, не существует. Строка с нулём отбрасывается
   так же, как отрицательная, и вызывающий падает на зеркало (DPD EE курьер
   6,82 €). Тест в `tests/shipping-montonio.test.ts`.

2. **Экран показывал live, а счёт выставляло зеркало.** Выбран второй путь из
   двух: **экран перестаёт обещать live**. Касса обязана оставаться
   синхронной и чистой функцией — `quoteFromRules()` не может ходить в сеть,
   и код это уже утверждает («Neither source is wired into checkout pricing»).
   Значит согласовывать надо в другую сторону: подсказка под полем считается из
   того же `src/data/montonio-tariffs.json`, из которого считает касса и запрет
   сохранения. `loadShipLiveRates()` с экрана уходит.
   Заодно запрет сохранения начинает сравнивать с **той же** ценой, что
   написана под полем (`carrierPrice`/`courierPrice`), а не с сырым тарифом, —
   иначе его собственный совет «очистите поле» давал цену выше той, которую он
   только что разрешил сохранить.

## 7. Страница «Доставка и оплата»

Рендерер остаётся один (`deliveryPageHTML`, `tableOnly` для превью в панели).
В него добавляется `ctx.montonio` — то же зеркало — потому что сегодня
`parcelCell()` при пустой ячейке перевозчика падает на `methods.parcel`, а касса
в этом месте берёт цену Montonio. На дефолтах это не видно (ячейки заполнены),
но стоит владельцу очистить одну — страница и касса разойдутся. Та же добавка
для курьера. `tools/prerender-shop2.mjs` поднимает новое объявление
`MONTONIO_PRICE` рядом с `SHIP_RULES`.

## 8. Чем доказывается «цены не изменились»

`tests/shipping-rate-table.test.ts`: 216 замороженных цен (страна × способ ×
перевозчик, включая Venipak, «EU» и незнакомую страну) прогоняются через
`quoteFromRules()` и через дефолты, и через разобранную строку настроек
продакшена — в том числе со старым `markup: {percent: 30, fixed: 5}` в строке.
Ни одно число не двигается.
