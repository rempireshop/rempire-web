# Доставка — тарифы, перевозчики, пакоматы

Три вещи, которые здесь описаны: **сколько стоит доставка** (правила в базе,
`src/lib/shipping.ts`), **откуда берётся список пакоматов**
(`src/lib/parcel-points.ts`, `tools/fetch-parcel-points.mjs`) и **как из админки
оформляется отправление и печатается этикетка** (Montonio Shipping,
`src/lib/shipping/montonio.ts`, раздел 3).

---

## 1. Тарифы: `settings.shipping_rules`

Цены живут в базе, в таблице `settings` под ключом `shipping_rules`, — чтобы
менять их из админки без выкладки. Строку создаёт миграция
`db/migrations/030_shipping_rules.sql` (числа брифа), а следующая за ней
`031_shipping_rules_ee_tariffs.sql` сразу поднимает в ней пакомат и курьер
Эстонии до сверенных тарифов — так что свежая база после `npm run migrate`
содержит `freeFrom` и `methods` ровно как ниже, и это те же числа, что
`DEFAULT_SHIPPING_RULES` в `src/lib/shipping.ts`. Если строки (или всей базы)
нет, код берёт их из себя, и заказ всё равно считается.

```json
{
  "freeFrom": 59,
  "freeFromByCountry": { "FI": 99, "LV": null },
  "methods": {
    "parcel":  { "default": 4.99, "EE": 5.47, "LV": 4.99, "LT": 4.99 },
    "courier": { "default": 9.90, "EE": 10.84 },
    "pickup":  { "default": 0 }
  },
  "carriers": {
    "omniva": { "EE": 3.29 },
    "dpd":    { "default": 6.50 }
  }
}
```

`freeFromByCountry` и `carriers` в примере показывают форму — миграции их не
создают, они появляются только из админки.

| Ключ | Что делает |
| --- | --- |
| `freeFrom` | Сумма корзины (€, **до скидки**), с которой доставка бесплатна. `null` — бесплатной доставки нет вообще. |
| `freeFromByCountry` | Переопределение порога по стране. `null` для страны — там никогда не бесплатно. |
| `methods` | Цена по способу и стране. `default` — для всех стран, что не названы. |
| `carriers` | Необязательное переопределение цены по перевозчику; сильнее `methods`. |

Правила разбираются по одному ключу: кривое или недописанное значение
откатывается к значению по умолчанию, а не роняет оформление заказа. Порог
считается **до** промокода — так принято, и корзина не теряет уже заработанную
бесплатную доставку из-за скидки.

Три способа доставки: `parcel` (пакомат), `courier` (курьер до двери),
`pickup` (самовывоз на Mardi 1; всегда бесплатно и только по Эстонии). Витрина
шлёт свои названия на трёх языках («Пакомат Omniva», «DPD kuller») — их
приводит к трём значениям `normalizeMethod()`.

### Страна заказа и строка тарифа — разные вещи

Ключи правил — это **строки таблицы**: `EE`, `LV`, `LT`, `FI`, `EU` («Другие
страны Европы») и `default` («Остальные страны»). Заказ же несёт **настоящую
страну** покупателя (`DE`, `IT`, …): посылку нельзя зарегистрировать «в
Европу», перевозчику нужна страна. В оформлении за выбором «Другая страна
Европы» стоит второй список — какая именно (`[data-countryiso]`, названия из
браузера на языке витрины) — и в `shipping.country` уходит код ISO.
`shippingZone()` в `src/lib/shipping.ts` переводит его обратно в строку:
четыре именованные страны — в себя, ЕС-27 плюс Исландия, Лихтенштейн,
Норвегия, Швейцария и Британия — в `EU`, всё остальное — в `default`. Заказы,
оформленные до этого (в них стоит голое `EU`), считаются по строке `EU`, но
зарегистрировать отправление по ним нельзя — админка так и говорит: «в заказе
не указана страна, уточните у покупателя». Тесты — `tests/shipping.test.ts`,
блок «zones».

### Цены по умолчанию и цены перевозчиков — это разные числа

В коде и в миграции 030 по-прежнему лежат числа из брифа для Латвии, Литвы и
«прочих стран»: пакомат LV/LT 4.99, курьер `default` 9.90, бесплатно от 59 €.

**Пакомат и курьер Эстонии — больше не эти числа.** Раньше это тоже был бриф
(3.49 / 5.99); исследование тарифов Montonio 03.09.2026 (раздел «Тарифы
Montonio» ниже) показало, что оба сидели ниже любого сверенного тарифа
Omniva/SmartPosti/DPD по Эстонии — то есть магазин продавал доставку у себя
дома дешевле, чем она стоила, с первого дня. `DEFAULT_SHIPPING_RULES` в
`src/lib/shipping.ts` несёт теперь 5.47 € (пакомат) и 10.84 € (курьер) —
верхнюю границу по сверенным тарифам, подробности в комментарии там же.

Миграция 030 при этом всё ещё сеет 3.49 / 5.99: она уже выполнена на боевой
базе (03.09.2026), и выполненную миграцию не переписывают. Поэтому следом идёт
`db/migrations/031_shipping_rules_ee_tariffs.sql`: она поднимает эти две клетки
в уже существующей строке до 5.47 / 10.84 — но только там, где всё ещё стоит
число брифа, каждую клетку по отдельности. Клетку, которую Ренат успел поменять
руками или кнопкой «Заполнить по тарифам Montonio», она не трогает; остальную
таблицу — LV/LT, `default`, порог, перевозчиков, наценку — тоже; строку, которой
нет, не создаёт. Повторный запуск ничего не меняет. На боевой базе 031
применится при следующей выкладке (`postbuild` → `migrate --if-configured`)
или через `POST /api/admin/migrate` — до этого там по-прежнему 3.49 / 5.99.
Проверено в `tests/shipping-migration.test.ts`.

**LV, LT и `default`/`EU` — по-прежнему не тронуты, и это осознанно, не
забывчивость.** Таблица в разделе «Тарифы Montonio» показывает их настоящую
цену — LV/LT пакомат 8,06–11,79 € против дефолтных 4,99 €, курьер 16–26 €
против 9,90 € — но решить, продолжает ли магазин доплачивать за доставку в эти
страны ради конверсии, или поднимать цены везде, должен Ренат, а не код.
Закрыть разницу одним нажатием можно в «Настройки → Доставка» кнопкой
**«Заполнить по тарифам Montonio»** — она пересчитывает все известные тарифу
клетки (EE, LV, LT, FI) сразу, с наценкой, если она задана.

Менять их нужно в `settings.shipping_rules` — из админки, а не в коде.

### Тарифы Montonio

Исследовано 03.09.2026: <https://montonio.com/pricing/>,
<https://docs.montonio.com/api/shipping-v2/reference>,
<https://docs.montonio.com/api/shipping-v2/guides/shipping-methods>.

**Публичного прайс-листа у Montonio нет.** На `montonio.com/pricing/` —
таблица тарифов по перевозчикам (DPD, Unisend, Omniva…) и странам (EE, LV,
LT, FI, SE), но вместо цифр — прочерки; реальные числа открываются только
вошедшему в личный кабинет продавцу. Там же — рекламная строка «Ship for just
€1.99/parcel» (не тариф, а нижняя планка «от») и тарифные планы подключения:
Starter 11.99 €/мес, Core 14.99 €/мес + 5 €/мес за прямую интеграцию
перевозчика сверх тех, что даёт Montonio, Core Flex 39.99 €/мес (прямые
интеграции включены). Для остальной Европы — отдельный калькулятор,
<https://shipping-calculator.montonio.com/>, тоже без цифр без входа.

**Зато в Shipping API v2 есть боевой эндпоинт для расчёта:**

```
POST /shipping-methods/rates
{ "destination": "EE",
  "parcels": [{ "items": [{ "length": 30, "width": 30, "height": 30,
                             "dimensionUnit": "cm", "weight": 5, "weightUnit": "kg",
                             "quantity": 1 }] }] }
→ { "carriers": [{ "carrierCode": "omniva",
      "shippingMethods": [{ "type": "pickupPoint",
        "subtypes": [{ "code": "parcelMachine", "rate": "2.50", "currency": "EUR" }] }] }] }
```

Авторизация та же, что у остальной Shipping API — Bearer JWT из
`accessKey`/`exp` (раздел 3). Один запрос — один результат сразу по всем
перевозчикам и способам, включённым у этого магазина в этой стране;
выключенный или ещё не активированный перевозчик просто не появляется в
ответе. НДС в ответе никак не помечен (в отличие от прайс-листов
перевозчиков, где это явно написано) — сверить на первом боевом запросе.
Реализовано в `fetchMontonioRates()`, `src/lib/shipping/montonio.ts`.

**Значит: живые тарифы есть, но только после того, как Ренат подключит
перевозчиков в личном кабинете Montonio** (раздел 3, «Что делает Ренат») — до
этого момента, и вообще без ключей, эндпоинту нечего отвечать. Поэтому у
магазина есть резервная таблица.

#### Резервная таблица — `src/data/montonio-tariffs.json`

Пока живых тарифов нет, `src/lib/shipping/tariffs.ts` берёт числа из этого
файла. Это не тарифы самого Montonio (он их не публикует) — это собственные
бизнес-прайс-листы перевозчиков (Omniva, SmartPosti, DPD), уже найденные и
сверенные для `public/shop/shipping-data.js` 03.09.2026 (источники — там же,
по URL на каждую строку). Приближение осознанное: Montonio рекламирует
«Pre-negotiated rates with top carriers» — то есть свою цену не выше
прайс-листа перевозчика, обычно ниже, так что прайс-лист — надёжная верхняя
граница, а не выдумка. Как только Ренат подключит перевозчиков и появятся
боевые ключи, `fetchMontonioRates()` начнёт отвечать, и
`getMontonioTariff()`/`getMontonioTariffsForCountry()` в `tariffs.ts` сами
предпочтут его этой таблице — «(a) живая цена… при недоступности — резервная
таблица» из брифа, буквально.

Каждая строка: перевозчик, страна, способ (`parcel`/`courier`), цена с НДС,
дата прайс-листа, ссылка на источник; у двух строк (DPD Финляндия, оба
способа) — `uncertain: true`: столбец страны в исходном PDF не удалось
выровнять с заголовком однозначно при извлечении текста — та же оговорка
`verify`, что и в `public/shop/shipping-data.js`.

Чего в таблице нет и почему:

- **Venipak, Unisend** — прайс-листа не нашлось вообще ни на одном языке.
  Появятся, когда либо Ренат включит их в Montonio (тогда их отдаст
  `fetchMontonioRates()`), либо кто-то найдёт публичный прайс-лист и допишет
  `src/data/montonio-tariffs.json` руками.
- **Курьер по зоне.** У DPD курьер режется по трём зонам (город/пригород,
  область, остальная страна) — EE зона 1&2 (Таллинн, Тарту и крупные города)
  8,99 €, зона 4 (остальная Эстония) 10,78 €; у LV/LT так же зона 1
  (Рига/Вильнюс-Каунас) дешевле, зона 3 дороже. Чекаут не спрашивает зону
  заранее, а `settings.shipping_rules` не умеет её хранить, поэтому таблица
  берёт **самую дорогую зону страны** — иначе доставка в область продавалась
  бы ниже себестоимости. Дешёвая зона видна в `src/data/montonio-tariffs.json`
  построчно, если Ренат решит, что для простоты выгоднее одна цена подешевле
  и небольшой убыток на дальних заказах.
- **«Другие страны Европы» / «Остальные страны».** Тариф DPD по Европе — это
  полоса по странам (21–45 € без НДС при 10 кг,
  `public/shop/shipping-data.js` → `restOfEuropeAt10kg`), а не одно число
  одного перевозчика. Свернуть её в одну строку значило бы придумать новый
  «дефолт» — то самое, ради чего эта таблица существует, — так что `EU` и
  `default` она не трогает вообще.

#### Обновление — `tools/fetch-montonio-tariffs.mjs`

```bash
node tools/fetch-montonio-tariffs.mjs                  # EE, LV, LT, FI
node tools/fetch-montonio-tariffs.mjs --countries ee,fi
node tools/fetch-montonio-tariffs.mjs --dry             # посчитать, не писать
```

Без ключей — печатает инструкцию (что нужно от Рената, откуда брать числа
руками) и заканчивается ненулевым кодом; ничего не пишет. С ключами — зовёт
`POST /shipping-methods/rates` для каждой страны и **дополняет** файл:
обновляет только те строки, которые Montonio реально вернул, остальное
(Venipak, Unisend, всё, что ещё не включено в личном кабинете) не трогает.

### Редактор тарифов в админке

**«Настройки → Доставка»** — таблица, а не справка. Строки: EE, LV, LT, FI,
«Другие страны Европы» и «Остальные страны» (это ключ `default`); колонки:
пакомат, курьер, самовывоз и «Бесплатно от». Ниже — сворачивающийся блок «Цены
по перевозчикам» (Omniva, SmartPosti, DPD, Venipak по странам, где они вообще
предлагаются): заполненная клетка сильнее таблицы выше.

- Пустая клетка — «нет своей цены», берётся строка «Остальные страны»
  (`default`).
- Слово **«нет»** в колонке «Бесплатно от» — в эту страну доставка не бывает
  бесплатной ни при какой сумме (`freeFromByCountry: {"LV": null}`).
- Цены принимаются от 0 до 99 €, с запятой или точкой, до двух знаков.
  Всё остальное просто не записывается в черновик.
- **«Сохранить тарифы»** пишет весь набор целиком через
  `PUT /api/admin/settings {shipping_rules}`, попадает в «Журнал изменений» и
  отменяется оттуда же. **«Вернуть значения по умолчанию»** возвращает числа из
  `DEFAULT_SHIPPING_RULES`.
- Серым текстом под каждой клеткой EE/LV/LT/FI, где он известен, — «тариф
  Montonio: 4,49 €» (только справка, само поле им не заполняется).
- **«Заполнить по тарифам Montonio»** пишет в таблицу тариф плюс наценка,
  округлённые вверх до цены на «…,X9 €» (никогда не вниз — чтобы наценка не
  съедалась округлением), для каждой клетки EE/LV/LT/FI, где тариф известен;
  Venipak, Unisend, «Другие страны Европы» и «Остальные страны» не трогает —
  под ними просто нет подсказки. Наценка — два поля тут же, «Наценка, %» и
  «Наценка, €» (`settings.shipping_rules.markup`, по умолчанию 0/0): цена =
  `тариф × (1 + % / 100) + €`, округлено вверх до «…,X9». Кнопка идёт через
  тот же `demoApply({type:"set_shipping_rules"})`, что и «Сохранить» — тоже в
  журнале, тоже с отменой. Расчёт — `computeMontonioFillPatch()` в `app.js`,
  ручное зеркало `src/lib/shipping/tariffs.ts` (`suggestShippingRulesFromTariffs()`,
  протестировано в `tests/shipping-tariffs.test.ts`); в браузере зеркало, а не
  сам модуль, потому что живой тариф Montonio требует `MONTONIO_SECRET_KEY`, а
  ему нельзя попадать в браузер — кнопка сейчас работает на резервной таблице
  (см. «Тарифы Montonio» выше), не на живом запросе.
- Помощник умеет то же самое одной фразой — «сделай доставку в Латвию 6,90»
  (действие `set_shipping_rules`, частичное: меняется только названная клетка).
  Наценку так пока не задать — `sanitizeShippingRules()` не знает про `markup`.

До этого редактора панель печатала прайс-лист перевозчиков (`SHIP.EE` в
`app.js`), а касса считала по `SHIP_RULES`: владелец читал одно число, магазин
брал другое. Теперь и то и другое — одна строка в базе.

Через SQL, если нужно:

```sql
update settings set value = '{ … }'::jsonb, updated_at = now()
where key = 'shipping_rules';
```

Витрина берёт те же правила через `GET /api/overrides` (`settings.shipping_rules`)
— при загрузке страницы, а не только при оформлении, — так что обещание
«бесплатно от 59 €» в шапке, в подвале и на карточке товара всегда равно тому,
что посчитает сервер. Если API недоступен (прототип лежит статикой), она
работает на встроенных значениях по умолчанию.

`src/lib/shipping.ts` держит строку в памяти инстанса минуту; сохранение из
админки сбрасывает этот кэш (`resetShippingRulesCache()` в
`PUT /api/admin/settings`), поэтому новая цена действует со следующего заказа,
а не через минуту.

## 2. Пакоматы: `GET /api/shipping/points/`

```
GET /api/shipping/points/?country=EE&carrier=omniva|dpd|smartpost|venipak|all
→ { ok, country, carrier, source, count, points: [
      { id, carrier, name, address, city, zip, lat, lng, type } ] }
```

`type` — `parcel_machine`, `pickup_point` (пункт выдачи в магазине) или
`post_office`.

`source` говорит, откуда ответ:

| Значение | Что это |
| --- | --- |
| `montonio` | Montonio Shipping — все перевозчики по одной паре ключей (раздел 3) |
| `live` | публичный фид перевозчика |
| `cache` | тот же фид, в памяти инстанса 6 часов |
| `seed` | запасной файл в репозитории |
| `montonio+seed` | часть перевозчиков от Montonio, остальные из запасного файла |

Ответ кэшируется на CDN на час (`s-maxage=3600`), ответы Montonio — ещё и на
6 часов в памяти инстанса.

Неизвестный перевозчик — **не ошибка**: маршрут отвечает `{ ok: true, points: [] }`,
и витрина просто убирает эту кнопку. Ошибка 400 оставила бы в оформлении заказа
перевозчика, из списка которого нечего выбрать.

### Кнопки перевозчиков в оформлении

`CARRIERS_BY_COUNTRY` в `public/shop2/app.js` перечисляет, о ком **вообще стоит
спросить**, а не кто точно есть: EE — Omniva, SmartPosti, DPD, Venipak; LV и
LT — Omniva, DPD, Venipak; FI — SmartPosti, DPD. При открытии шага доставки
витрина спрашивает списки сразу по всем перевозчикам страны, и тот, у кого
список пуст, исчезает до того, как на него нажмут. Поэтому DPD и Venipak
появляются ровно там, где Montonio их отдал, а Финляндия получает пакомат в тот
день, когда Montonio вернёт финские точки, — без ещё одной выкладки.

### Логотипы перевозчиков — `GET /carriers`

Ренат, 07.09.2026: «есть ли у Montonio логотипы пакоматов (Omniva и других)?
Сейчас там просто какие-то цвета». Цвета — это правда: кнопка перевозчика в
кассе рисуется точкой-кружком из CSS, `public/shop2/styles.css`, правила
`.carrier[data-carrier="omniva"]::before` и соседние (Omniva `#f47a20`, DPD
`#dc0032`, SmartPosti жёлто-чёрный, Venipak `#1e4b9d`, Unisend `#7dd957`).
Сама кнопка — `public/shop2/app.js`, `'<button class="carrier" …>' +
CARRIER_NAMES[c]`.

**Логотипы у Montonio есть — но не там, где мы смотрим.** Проверено по
справочнику Shipping API v2 (сверено 07.09.2026):

| Эндпоинт | Есть `logoUrl`? |
| --- | --- |
| `GET /shipping-methods` | нет |
| `GET /shipping-methods/pickup-points` | нет (`id`, `name`, `type`, `streetAddress`, `locality`, `postalCode`, `carrierCode`, `additionalServices`) |
| **`GET /carriers`** | **да** |

Ответ `GET /carriers` — по объекту на перевозчика: `id`, `code`, `name`,
**`logoUrl`**, `contracts`, `hasMontonioContract`, `supportedContractTypes`.
`logoUrl` — это SVG на публичном хосте Montonio, вида
`https://public.montonio.com/images/carrier_logos/smartpost.svg`.

Мы этот эндпоинт **не вызываем**: `src/lib/shipping/montonio.ts` ходит в
`/shipping-methods/pickup-points`, `/shipping-methods/courier-services`,
`/shipping-methods/rates`, `/shipments` и `/label-files`. Чтобы заменить
кружки на логотипы, нужно: наш маршрут (по образцу
`GET /api/payments/methods/`, который так же даёт `logoUrl` банкам), кэш на
те же 6 часов, и `<img>` вместо `::before` в кнопке перевозчика. Это меняет
внешний вид кассы, поэтому сделано не будет, пока Ренат не скажет —
вопрос 3 в `docs/audit/2026-09-07-montonio.md`.

Картинку отдаёт домен Montonio, а не наш, но правку CSP это не потребует:
`img-src 'self' data: https:` в `next.config.ts` уже разрешает любой https —
логотипы банков приходят оттуда же и рисуются.

### Что реально есть у каждого перевозчика

Проверено 03.09.2026.

| Перевозчик | Публичный фид | Как получаем |
| --- | --- | --- |
| **Omniva** | Есть: <https://www.omniva.ee/locations.json> — один файл на EE, LV и LT, без ключа, CORS открыт | Живой запрос + кэш 6 ч, или Montonio |
| **SmartPosti** (Itella/Posti) | Нет массовой выдачи: сайт отдаёт список слагов, а детали — по одному запросу (~60 КБ) на точку | Seed-файл, или Montonio |
| **DPD** | Нет вообще. Публичные адреса (`api.dpd.lt`, `parcelshop-finder.dpd.com`) больше не существуют | **Только Montonio** (или договор DPD, см. ниже) |
| **Venipak** | Нет | Только Montonio |

Две ловушки Omniva, из-за которых нельзя просто скопировать поля:

- `X_COORDINATE` — это **долгота**, `Y_COORDINATE` — **широта**. Названия
  читаются наоборот.
- `ZIP` у пакомата — **не почтовый индекс**, а внутренний код терминала
  (он уникален для всех 1442 строк). Мы используем его как `id` и никогда как
  индекс на посылке. Настоящий индекс есть только у 32 почтовых отделений
  (`TYPE=1`).

**DPD.** Свой адрес у DPD есть — `https://integration.dpd.ee/ws-mapper-rest/parcelShopSearch_`
(и `.lv`, плюс `integracijos.dpd.lt`), но он требует логин и пароль от договора
DPD Baltics. Если они появятся — положить их в `DPD_API_USER` и `DPD_API_PASS`,
и точки начнут приходить и в API, и в seed без единой правки кода. **Проще
другое: те же точки DPD отдаёт Montonio** — по ключам, которые уже есть для
оплаты (раздел 3). Пока нет ни того, ни другого, DPD предлагается только как
курьер, а кнопка «DPD» в выборе пакомата пропадает сама.

**Финляндия.** Omniva там не работает. У SmartPosti финских точек 3333, но
детальные страницы для них на эстонском домене не существуют: все 3333 адреса
отдают 404 (проверено — скрипт скачал список и не смог получить ни одной
карточки). Официальный путь мимо Montonio — Posti Pickup Point API
`https://gateway.posti.fi/2025-04/pickuppoints/FI`, ему нужен Bearer-токен
(старый Location Service отключён 31.03.2026). **С Montonio финские пакоматы
появятся сами**, как только Ренат подключит там перевозчика с точками в
Финляндии: витрина спрашивает про FI на каждом оформлении и показывает пакомат,
если в ответе есть хоть одна точка. Без Montonio и без токена Posti в Финляндию
по-прежнему предлагается только курьер.

## 3. Montonio Shipping — все перевозчики по одной паре ключей

Файл `src/lib/shipping/montonio.ts`, документация Montonio —
<https://docs.montonio.com/api/shipping-v2/reference> (сверено 03.09.2026).

**Зачем.** Публичные фиды закрывают только Omniva. Montonio перепродаёт Omniva,
DPD, Itella SmartPosti и Venipak по **тем же ключам, что уже стоят для оплаты**
(`MONTONIO_ACCESS_KEY`, `MONTONIO_SECRET_KEY`, `MONTONIO_ENV`) — отдельного
договора и отдельного ключа не нужно. И он же оформляет отправление и печатает
этикетку, так что Ренат не переписывает адреса в личные кабинеты перевозчиков.

### Что делает Ренат

1. В партнёрской системе Montonio (<https://partner.montonio.com>, для тестов
   <https://sandbox-partner.montonio.com>) — раздел **Shipping** → включить
   перевозчиков, которых хочет предлагать. Договор можно взять у самого
   Montonio (`hasMontonioContract`) или подключить свой.
2. Указать там же адрес отправителя — он подставляется в каждое отправление,
   в коде его нет.
3. Больше ничего. Ключи те же, что для оплаты.

### Что видит Ренат в админке

Карточка заказа — это полоса из четырёх шагов, **Оплачен → Этикетка →
Отправлен → Доставлен**, и под ней одна главная кнопка: та, что делает
следующий шаг. Каждый шаг — отдельное нажатие, каждый попадает в журнал
(«Настройки → Журнал изменений») с кнопкой «Вернуть».

1. **«Создать этикетку»** — у оплаченного заказа с пакоматом или курьером.
   Одно нажатие: Montonio регистрирует посылку у перевозчика и возвращает
   трек-номер. **Статус заказа при этом не меняется** — этикетка это
   наклейка, а не передача посылки; заказ остаётся «Оплачен», в списке
   переходит из «Новые» в «Этикетка готова». (Раньше эта кнопка сама
   переводила заказ в «Отправлен» и отправляла письмо — ровно то, на что
   жаловался Ренат: «нажимаю „этикетка“ — меняется весь статус».)
   Появляется блок **«Отправление»**: перевозчик и пункт, трек-номер с
   кнопкой «Скопировать», **код сдачи посылки** (`dropOffPin`, у некоторых
   перевозчиков — с ним посылку можно сдать в пакомат без печатной
   наклейки), и этикетка двумя ссылками: **«Открыть PDF (A4)»** для
   обычного принтера и **«A6 для термопринтера»**. Ссылка «Отследить» ведёт
   на страницу перевозчика.
2. **«Отправлен»** — посылка ушла. Сначала карточка подтверждения: она
   называет письмо, которое уйдёт покупателю, и трек-номер, который в нём
   будет (или говорит, что трек-номера нет). После «Отправлен» статус
   становится `shipped`, покупателю уходит «Заказ отправлен» со ссылкой на
   отслеживание. Кнопка есть и без этикетки — курьер, который забирает
   посылку сам, или передача из рук в руки: тогда письмо уходит без
   трек-номера, а шаг «Этикетка» в полосе остаётся с пометкой «без
   этикетки».
3. **«Доставлен»** — последний шаг, вручную, без письма: статус
   `delivered`. Заказ переходит в «Доставлены» и по-прежнему считается
   продажей в «Обзоре» и «Аналитике» (`PAID_STATUSES` в
   `src/lib/analytics.ts` — `paid | shipped | delivered`).

Самовывоз: этикетки и «Отправлен» нет — у такого заказа два шага, **Оплачен
→ Выдан**, и кнопка «Выдан клиенту» (тот же статус `delivered`, письма нет:
покупатель только что вышел с пакетом). Продажа в салоне: вместо доставки
ссылка «Чек». Заказ из одних подарочных карт: полосы нет, отправлять нечего.

**Отмена шага.** «Вернуть» в журнале (или «Отменить» на всплывающей полоске
сразу после нажатия): «Доставлен» → снова `shipped`, «Отправлен» → снова
`paid`, письмо второй раз не уходит. Отмена этикетки — особый случай:
**зарегистрированное отправление у Montonio отменить нельзя**, поэтому
запись о нём остаётся на заказе, а карточка возвращает шаг «Этикетка» и
говорит об этом прямо (блок «Отправление» гаснет, в нём — «Отправление у
Montonio остаётся — отменить его нельзя»). Следующее «Создать этикетку»
возвращает ту же этикетку, второй посылки не заказывает.

Второе нажатие «Создать этикетку» ничего не создаёт: маршрут возвращает уже
сохранённое отправление, чтобы не заказать (и не оплатить) вторую посылку.

**Список «Заказы».** Фишки **Новые · Этикетка готова · Отправлены ·
Доставлены · Салон · Все** — по тем же шагам; у первых двух живой счётчик.
«Ждут отправки» в «Обзоре» (и значок на кнопке «Заказы») — это **все
оплаченные веб-заказы, с этикеткой и без**: наклейка не делает посылку
отправленной, она всё ещё на полке. То есть «Отправить N» = «Новые» +
«Этикетка готова» (`ordersToShip` в `src/lib/analytics.ts`,
`admWaitingCount()` в `app.js`). Заказы, ждущие оплаты, лежат в «Все» со
своим бейджем «Ждёт оплаты».

### Адреса и авторизация

| | |
| --- | --- |
| Боевой | `https://shipping.montonio.com/api/v2` |
| Песочница | `https://sandbox-shipping.montonio.com/api/v2` |

Авторизация — **JWT в заголовке**, не в теле запроса (этим Shipping API
отличается от Orders API, где подписанный payload лежит в `{ data: … }`):

```
Authorization: Bearer <HS256 { accessKey, exp }>
```

Подписывается тем же `MONTONIO_SECRET_KEY`, алгоритм HS256, срок жизни — час
(рекомендация из документации). Используется тот же `src/lib/payments/jwt.ts`,
новых зависимостей не появилось.

**Про лимиты запросов в документации не сказано ничего** — ни в обзоре, ни в
справочнике. Поэтому списки точек кэшируются на 6 часов, как и фиды.

### Эндпоинты, которые мы используем

| Метод | Путь | Зачем |
| --- | --- | --- |
| `GET` | `/shipping-methods` | какие перевозчики включены в стране |
| `GET` | `/shipping-methods/pickup-points?carrierCode=&countryCode=&type=` | список точек |
| `GET` | `/shipping-methods/courier-services?carrierCode=&countryCode=` | id курьерской услуги |
| `POST` | `/shipments` | создать отправление |
| `GET` | `/shipments/{id}` | перечитать статус и трек-номер |
| `POST` | `/label-files` | создать файл этикеток |
| `GET` | `/label-files/{id}` | ссылка на готовый PDF |

Точка выдачи приходит так (поля скопированы из справочника, а не придуманы):

```json
{ "pickupPoints": [ {
    "id": "98b391d7-5299-447c-9ad7-6b4042ef8b2f",
    "name": "Laagri Coop Maksimarketi pakiautomaat",
    "type": "parcelMachine",
    "streetAddress": "Pärnu mnt 558a",
    "locality": "Laagri alevik",
    "postalCode": "96067",
    "carrierCode": "omniva",
    "additionalServices": [ { "code": "cod" } ] } ],
  "countryCode": "EE" }
```

Две вещи, которые из этого следуют:

- **Координат в ответе Montonio нет вообще.** Ни `latitude`, ни `longitude` —
  проверено по списку полей в справочнике. Поэтому у точек Montonio `lat` и
  `lng` равны `null`, и координаты остаются только у точек из фидов. Карту
  выбора пакомата на них строить нельзя.
- `id` — это UUID Montonio, и **только им** можно адресовать отправление.
  Если покупатель выбрал точку из фида (id вида `omniva-96243`), при создании
  отправления она сопоставляется обратно по названию; если совпадения нет,
  маршрут отвечает `point_unresolved`, а не отправляет посылку не туда.

**Перевозчик в заказе хранится.** Витрина шлёт `shipping.carrier` («omniva»,
«smartpost», «dpd» или «venipak»; для курьера — пустую строку), и
`createOrder()` в `src/lib/orders.ts` кладёт его в `orders.shipping.carrier`:
обрезанным, в нижнем регистре, не длиннее 20 символов и только из этого списка,
всё остальное превращается в `null`. При создании отправления перевозчик
берётся по порядку: что указал админ в теле запроса → `shipping.carrier` из
заказа → для заказов, оформленных до того, как поле стали хранить, — префикс
идентификатора точки из фида (`omniva-96243`) и название перевозчика внутри
старой текстовой подписи способа («Пакомат Omniva»). Для пакомата это почти
всегда неважно: UUID точки Montonio сам задаёт перевозчика, и в ответе на
создание отправления приходит настоящий `carrierCode`. Для курьера витрина
перевозчика не спрашивает, поэтому, если админ его не указал, берётся первый
перевозчик с курьерской услугой в этой стране.

Отправление создаётся синхронно (`synchronous: true`): админ нажал кнопку и
должен увидеть трек-номер на экране, а не через вебхук. Поэтому **вебхуки
Montonio Shipping мы не регистрируем.** Они есть — `shipment.registered`,
`shipment.registrationFailed`, `shipment.labelsCreated`, `shipment.statusUpdated`,
`labelFile.ready`, `labelFile.creationFailed`; на магазин их можно завести до
десяти, тело POST-а — `{ payload: <JWT> }`, подписанный тем же секретом, шлются
с адресов `35.156.245.42` и `35.156.159.169`. Понадобятся, если появится
массовая печать этикеток или живой статус доставки на странице заказа.

### Маршруты магазина

```
POST  /api/admin/shipments/           { orderId }            → { ok, shipment, order }   статус заказа не трогает
GET   /api/admin/shipments/<id>/label/?size=A4|A6            → PDF                       A4 по умолчанию
PATCH /api/admin/orders/<id>/         { status: "shipped" }  → статус + письмо «Заказ отправлен» с трек-ссылкой
PATCH /api/admin/orders/<id>/         { status: "delivered" } → последний шаг, без письма
PATCH /api/admin/orders/<id>/         { labelStep: false }   → отмена этикетки: запись остаётся, шаг возвращён
```

Все за `requireAdmin`. `<id>` — uuid заказа или его номер (`R-100042`).
Этикетка **проксируется**, а не отдаётся ссылкой: Montonio выдаёт подписанный
адрес S3, и ссылка на него была бы наклейкой, доступной кому угодно, пока
подпись жива.

`?size=A4` (по умолчанию) — одна этикетка на листе A4 для обычного принтера,
`?size=A6` — сама этикетка для термопринтера. Файл Montonio при этом
**чинится** (`src/lib/shipping/label-pdf.ts`): их генератор вкладывает
этикетку A6 в лист A4 (сдвиг + масштаб 1,85), а потом вкладывает этот лист
ещё раз с теми же сдвигом и масштабом — на A4 этикетка выходила в 3,4 раза
крупнее и на листе помещалась половина, на A6 то же самое при 0,95. Прокси
находит самую внутреннюю форму (саму этикетку) и рисует её заново: на A6
один к одному, на A4 — по центру с полями 10 мм. Файл без такой вложенности
(обычная страница, несколько этикеток на листе) уходит как есть. Тесты —
`tests/shipping-label-pdf.test.ts`.

Письмо «Заказ отправлен» уходит **только** из `PATCH … { status: "shipped" }`
(`src/app/api/admin/orders/[id]/route.ts`), и только при первом переходе в
`shipped`: возврат из `delivered` обратно в `shipped` письма не шлёт. Если на
заказе есть отправление Montonio, в письмо подставляются его `trackingCode`
и `trackingUrl`; если нет — письмо уходит без трек-номера. Обратный шаг из
`shipped`/`delivered` в `paid` (отмена из журнала) — тоже этот PATCH; он не
считает это «отметить оплаченным вручную» и деньги не трогает.

Результат кладётся в `orders.shipping.montonio` (слиянием, поля оформления не
затираются):

```json
{ "provider": "montonio", "shipmentId": "…", "status": "registered",
  "carrier": "omniva", "trackingCode": "CC543167770EE",
  "trackingUrl": "https://minu.omniva.ee/track/…", "dropOffPin": "4821",
  "labelUrl": "…", "labelSize": "A4", "dismissed": false, "createdAt": "…" }
```

`dismissed: true` — этикетка «отложена» отменой из журнала: отправление у
перевозчика есть, карточка показывает шаг как не сделанный. Следующий `POST`
снимает флаг и возвращает то же отправление (`reused: true`).

### Заглушка для тестов — `SHIPPING_PROVIDER=mock`

Браузерные тесты (`e2e/admin.spec.ts`) проходят весь путь карточки —
этикетка, письмо с трек-ссылкой, «Доставлен», отмена из журнала — без ключей
Montonio и без настоящих посылок: `playwright.config.ts` поднимает сервер с
`SHIPPING_PROVIDER=mock`, и `src/lib/shipping/montonio-mock.ts` подменяет
ровно три вызова — регистрацию отправления, файл этикетки и сам PDF. Точки,
перевозчики и тарифы не подменяются: с включённой заглушкой они ведут себя
как без ключей. Переключатель явный (по образцу `PAYMENT_PROVIDER=mock`) и
не работает под `NODE_ENV=production`; без него отсутствие ключей по-прежнему
означает `not_configured`, а не выдуманную посылку.

### Чего в коде нет и почему

- **Веса товаров в каталоге нет**, а Montonio его требует. Считаем оценкой:
  0,4 кг на единицу плюс 0,2 кг на упаковку, от 0,3 до 30 кг. Перевозчик
  взвесит посылку сам; если у договора включена обязательная проверка габаритов
  (`parcelDimensionsRequired: true`), запрос вернётся с 400, и текст ошибки
  Montonio будет виден в ответе админского маршрута.
- **Расчёт стоимости через Montonio** (`POST /shipping-methods/rates`)
  подключён (`fetchMontonioRates()` здесь, кэш и резервная таблица в
  `src/lib/shipping/tariffs.ts` — раздел 1, «Тарифы Montonio»), но не в само
  оформление заказа: цена, которую платит покупатель, по-прежнему целиком
  берётся из `settings.shipping_rules`, быстро и без сетевого запроса на
  каждый заказ. Тариф участвует только там, где магазин *решает*, какими
  быть этим числам — в кнопке «Заполнить по тарифам Montonio» в админке.
- Наложенный платёж (`cod`) и проверка возраста (`ageVerification`) не
  используются.

### Песочница

`MONTONIO_ENV=sandbox` (значение по умолчанию) — запросы уходят на
`sandbox-shipping.montonio.com`. Песочница не звонит перевозчикам: адреса и
телефоны не проверяются, этикетки рисуются заглушками, трек-номера не настоящие.
Перевозчиков в песочнице всё равно надо включить, но реквизиты договора можно
вписать любые. Переключать на `live` — только когда выданы боевые ключи;
песочные ключи на боевом хосте не работают, и наоборот.

## 4. Как обновить seed-файл

`src/data/parcel-points.seed.json` лежит в репозитории намеренно: витрина
должна предлагать пакомат и в день, когда сайт перевозчика лежит.

```bash
node tools/fetch-parcel-points.mjs                        # все перевозчики
node tools/fetch-parcel-points.mjs --carrier omniva       # только один
node tools/fetch-parcel-points.mjs --countries ee,fi      # страны SmartPosti
node tools/fetch-parcel-points.mjs --dry                  # посчитать, не писать
```

Что нужно знать перед запуском:

- Omniva — один запрос, секунда.
- SmartPosti — **один запрос на точку**. EE это 356 запросов (пара минут), FI —
  3333 (десятки минут и ~200 МБ трафика). Скрипт держит 6 параллельных
  соединений; не увеличивайте — это чужой сайт.
- Адрес детальной страницы содержит `buildId` сайта SmartPosti, который меняется
  при каждой их выкладке. Скрипт вычитывает его сам — не прописывайте руками.
- LV и LT у SmartPosti пока не собираются: локализованные адреса страниц
  (`/pakomati`, `/pastomatai`) отдают 404, путь ещё нужно найти.
- DPD добавится сам, если в окружении есть `DPD_API_USER` и `DPD_API_PASS`.

После запуска — посмотреть на счётчики в конце вывода и на размер файла, и
только потом коммитить.

## 5. Переменные окружения

Значения не хранятся в репозитории — только имена.

| Переменная | Зачем |
| --- | --- |
| `MONTONIO_ACCESS_KEY` | Access Key из партнёрской системы. **Тот же, что для оплаты** |
| `MONTONIO_SECRET_KEY` | Secret Key, им подписывается JWT. Тот же, что для оплаты |
| `MONTONIO_ENV` | `sandbox` (по умолчанию) или `live`. Общий с оплатой |
| `DPD_API_USER`, `DPD_API_PASS` | Прямой доступ к точкам DPD (нужен договор DPD Baltics). Не нужны, если работает Montonio |
| `POSTI_API_KEY` | Пока не используется — понадобится для точек SmartPosti в Финляндии мимо Montonio |

Без ключей Montonio всё работает как раньше: Omniva из фида, SmartPosti из
seed-файла, DPD и Venipak не предлагаются, «Создать этикетку» отвечает
«Доставка Montonio не подключена» (маршрут — `not_configured`); «Отправлен» и
«Доставлен» работают и без этикетки.

## 6. Страница «Доставка и оплата» на витрине

`/shop2/info/shipping/` (и `/shop2/et/info/shipping/`, `/shop2/en/info/shipping/`)
— больше не «Политика доставки» с нумерованными определениями, а страница,
которую покупатель читает перед оплатой. Адрес не менялся; прежний
юридический текст никуда не делся — он свёрнут внизу под заголовком
**«Полные условия доставки»** (владельческая замена из «Настройки →
О компании → правовые тексты», `content.legal.shipping`, подставляется туда
же).

Что на странице и откуда берётся каждая цифра:

| Блок | Откуда |
| --- | --- |
| **Способы и цены** — таблица страна · пакомат · курьер · бесплатно от | `settings.shipping_rules`, те же правила, по которым считает касса: `methods[способ][страна]` с откатом на `default`. Клетка пакомата — цена способа, или «от …» — самая низкая, если у перевозчиков этой страны заданы свои цены (`carriers`); страна без пакоматов (`EU`, у неё нет перевозчиков в `CARRIERS_BY_COUNTRY`) — прочерк. «Бесплатно от» — `freeFromByCountry[страна]`, иначе `freeFrom`; `null` печатается как «не бывает». |
| Перевозчики под названием страны | `CARRIERS_BY_COUNTRY` в `app.js` — те, о ком касса вообще спрашивает (раздел 2) |
| **Самовывоз в салоне** | адрес и часы работы из `settings.content` («Настройки → О компании»); «заказ ждёт 7 дней» — та же строка, что в подвале |
| **Сроки** | `DELIVERY_ROWS` в `app.js` — сроки, которые обещают условия доставки (`public/shop/legal.en.js`): Эстония 1–3 рабочих дня, Латвия/Литва/Финляндия 2–5, остальная Европа 3–8; заказ, оплаченный в рабочий день до 14:00, уходит в тот же день |
| **Оплата** | логотипы из `public/shop/paylogos.js` — те же, что в кассе; банки — из `GET /api/payments/methods/`, когда Montonio подключён (до этого — названия); счёт для компаний; подарочная карта; **баллы** — публичная часть `settings.pricing.loyalty` (включены ли и сколько процентов), строка исчезает, если баллы выключены |
| **Возврат товара** | три предложения (14 дней, как вернуть, вскрытая косметика) и ссылка на `/info/returns/` |
| **Вопросы** | телефон, почта, адрес, часы из `settings.content` и ссылка на «Контакты» |

### Как устроено

Одна функция — `deliveryPageHTML(ctx)` в `public/shop2/app.js`. Она нарочно
чистая: читает только `ctx` и ни одной переменной из замыкания. Витрина
вызывает её из `screenDelivery()` с живыми `SHIP_RULES`, контентом и
логотипами; `tools/prerender-shop2.mjs` вырезает её из `app.js` по строкам
(вместе с `SHIP_RULES`, `CARRIER_NAMES`, `CARRIERS_BY_COUNTRY` и
`DELIVERY_ROWS`) — так же, как он вырезает словарь, — и пишет статические
страницы **той же функцией**. Поэтому страница для робота и страница для
человека совпадают слово в слово, и добавлять новый блок нужно в одном месте.

Перевод: каждая строка страницы — отдельный текстовый узел, пропущенный через
`ctx.tr()`. В витрине это тождество (после рендера `translateTree()`
переводит узлы словарём), в prerender — сам словарь. Строки с числами
(«Начисляем 5 % …», «от 4,99 €») закрыты правилами `UI_RX`;
`node tools/i18n-gaps.mjs` должен показывать 0 пробелов.

Цены в статической странице: `tools/lib/settings-export.mjs` читает
`settings.shipping_rules` и `settings.pricing` прямо из Postgres, если при
сборке задан `DATABASE_URL` (на Vercel — задан), и сливает их поверх
`SHIP_RULES` тем же способом, что `applyShipRules()`; без базы печатаются
значения по умолчанию. Витрина в любом случае перерисовывает страницу из
`/api/overrides/` при загрузке, так что между изменением тарифа и следующей
выкладкой расходится только то, что видит робот.

Проверки: `e2e/info-pages.spec.ts` — цены из правил на трёх языках, логотипы
оплаты, свёрнутый юридический текст, изменённая в админке цена появляется
на странице, на телефоне таблица прокручивается внутри своей полосы, а
страница — нет; `tools/check-prerender.mjs` — статические страницы.
