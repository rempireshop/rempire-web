# Цены доставки: как выбрать число за час

Этот файл написан для одного конкретного дня — того, в который появились живые
ключи Montonio и надо решить, **сколько брать за доставку в каждую страну**.

Инструмент не выбирает цену. Он приносит настоящие цифры Montonio и считает,
что каждая цена-кандидат зарабатывает или теряет на разных размерах заказа.
Выбирает человек, потому что выбор — это ставка, а не вычисление.

```
node tools/delivery-pricing.mjs
```

---

## 1. Что нужно иметь под рукой ДО запуска

| Что | Где взять | Без этого |
| --- | --- | --- |
| `MONTONIO_ACCESS_KEY` | partner.montonio.com → Shipping → API keys | инструмент останавливается |
| `MONTONIO_SECRET_KEY` | там же | то же |
| `MONTONIO_ENV=live` | поставить руками | пойдёт запрос в песочницу, а там цены ненастоящие |
| **включённые перевозчики** | partner.montonio.com → Shipping | сетка придёт пустая |

Последняя строка — самая важная и её легко пропустить. В документации Montonio
на этом эндпоинте стоит примечание: *«This endpoint only returns rates for
carriers with Montonio contracts. Carriers that only support Direct contracts
will not be included in the response.»* То есть **перевозчик, у которого с
Montonio нет контракта, просто не появится в ответе**. Не с нулевой ценой — его
там не будет вовсе.

Поэтому дыры в таблице надо читать как «у магазина нет контракта на это», а не
как «здесь дёшево». Инструмент везде рисует `—` и ни в одном месте не
подставляет ноль.

Ещё стоит заранее ответить на один вопрос: **сколько единиц товара в обычном
заказе?** Два-три? Пять? Это единственное число, которое инструмент не может
узнать сам (см. § 5).

---

## 2. Команда

Обычный запуск — все страны, все веса, типичный заказ из 3 единиц:

```bash
export MONTONIO_ACCESS_KEY=...
export MONTONIO_SECRET_KEY=...
export MONTONIO_ENV=live

node tools/delivery-pricing.mjs
```

или `npm run delivery:pricing`. Идёт около минуты: один запрос на страну на
каждый вес, 25 стран × 5 весов.

С ключами удобнее без `export` — тогда переменные не останутся висеть в
терминале:

```bash
MONTONIO_ACCESS_KEY=... MONTONIO_SECRET_KEY=... MONTONIO_ENV=live \
  node tools/delivery-pricing.mjs
```

Через `npm run` аргументы надо отделять двумя дефисами:
`npm run delivery:pricing -- --units 5`. Проще звать `node` напрямую.

Полезные варианты:

```bash
# «в обычном заказе 5 банок, а самый большой реальный — 15»
node tools/delivery-pricing.mjs --units 5 --heaviest 15

# проверить конкретные цены, которые уже стоят в панели или обсуждаются
node tools/delivery-pricing.mjs \
  --flat-locker  EE=5.47,LV=5.59,LT=5.59,FI=7.89,EU=12.90 \
  --flat-courier EE=10.84,LV=9.90,LT=9.90,FI=15.69,EU=22.29

# только четыре домашние страны, быстро
node tools/delivery-pricing.mjs --countries EE,LV,LT,FI

# посмотреть, как инструмент выглядит, вообще без ключей
node tools/delivery-pricing.mjs --dry-run
```

`--flat-locker` и `--flat-courier` разделены не для красоты: это две разные
колонки на экране тарифов, и числа в них далеко не одинаковые (Эстония — 5.47 и
10.84). Одно число на обе колонки сравнило бы цену пакомата с себестоимостью
курьера и показало бы катастрофу, которой нет.

Отчёт пишется в `output/delivery-pricing-<дата>.md` — те же таблицы плюс полная
расшифровка запуска. `--out ПУТЬ` меняет адрес, `--json` кладёт рядом
машиночитаемую сетку.

## 3. Как читать вывод

Вывод идёт шестью блоками, сверху вниз — от фактов к решению.

### 3.1. Сетка: страна × вес × способ

Во что обходится посылка. Отдельная таблица на **пакомат**, **пункт выдачи**,
**почту** и **курьера** — и это главное, чего не было раньше: старая таблица
знала одну цену на весь «pickupPoint», а у Montonio там три разных тарифа.
Магазин мог платить за пакомат цену пункта выдачи, и заметить это было негде.

Колонка справа — перевозчик, чья цена взята. Правило то же, что во всём
магазине (`costBasis()`):

- **пакомат в EE, LV, LT, FI** — берётся **самый дорогой** перевозчик, потому
  что там покупатель сам жмёт фишку и может выбрать дорогого;
- **везде остальное** — **самый дешёвый**, потому что перевозчика выбирает
  Ренат, когда делает этикетку.

### 3.1a. Отдельно — EE, LV, LT, FI: у каждого перевозчика своя цена

Сетка выше показывает **одного** перевозчика на страну — того, чью цену клетка
обязана покрывать. Под «Пакоматом» в четырёх домашних странах этого мало:
чекаут рисует фишку на каждого перевозчика, покупатель жмёт сам, и в панели на
каждого заведена своя клетка. Поэтому по этим четырём странам печатается
дополнительная таблица — перевозчик × вес.

Одно число на всю страну здесь уже стоило денег: 13.09.2026 оказалось, что
девять из четырнадцати пар «перевозчик + страна» продавались ниже
себестоимости, и выбирал покупатель. Финляндия брала 7.89 € за пакомат DPD,
который стоит 12.39 €.

Nova Post в этой таблице есть и помечен «только фишка»: он сам себе цена, но
основой цены страны не становится никогда — у Montonio International Shipping
нет возвратов вообще.

### 3.2. За что Montonio берёт деньги

> **24.09.2026 — Montonio ответил, и этот раздел написан на неверной посылке.**
> «Our pricing for time being takes into account real weight. If that will
> change, then we'd let them know.» Объёмный вес (делитель на самом деле 4000)
> Montonio считает, но **в цену он сейчас не идёт**; у DPD за границей цена по
> маршруту — фиксированная, по весу или по категории коробки XS/S/M/L. Колонка
> «что решает» теперь пишет «цена — по весу» (или «коробка тяжелее, но цена — по
> весу»), а не «платим за КОРОБКУ». Переключатель на случай перемен —
> `MONTONIO_PRICES_VOLUMETRIC` в `src/lib/shipping/parcel.ts`; на этикетке с
> 24.09 объявляется 0,9 кг при любой коробке. Ниже — как рассуждали до ответа.

Небольшая таблица, которую стоит прочитать раньше всех остальных. Montonio
считает **тарифный вес** как максимум из настоящего и объёмного, а объёмный —
это габариты ÷ 5000. Коробка 30×30×30 — это 5.4 кг, что бы в неё ни положили.

Если в колонке «что решает» написано **«платим за КОРОБКУ»**, то на этой полке
цену задаёт упаковка, а не содержимое, и вопрос «сколько банок в заказе»
перестаёт что-либо менять. Это не ошибка расчёта, это то, как Montonio
выставляет счёт, — и это, между прочим, рычаг: коробка поменьше дешевле
любого торга о тарифе.

### 3.3. Какую цену ставить

Главная таблица. По каждой стране:

| Колонка | Что это |
| --- | --- |
| `себест. типичн.` | во что обходится заказ того размера, который назван типичным |
| `себест. макс.` | во что обходится самый тяжёлый заказ |
| `по типичному` | цена, которая окупает типичный заказ — **всё, что тяжелее, в минус** |
| `середина` | ровно между «по типичному» и «без убытка» — это и есть ставка |
| `без убытка` | окупает даже самый тяжёлый заказ; за него платят мелкие, которых большинство |
| `у вас` | то, что передано в `--flat-*` |
| `на макс.` | сколько остаётся на самом тяжёлом заказе при этой цене |
| `теряет с` | с какого размера заказа эта цена перестаёт окупаться |

Все три кандидата уже округлены по правилу магазина — вверх, до цены,
кончающейся на девять копеек. Их можно набирать в панель как есть.

«Терпимая середина» — это колонка `середина`, но выбирать её вслепую не надо:
смотреть надо на `теряет с`. Если цена начинает терять с 12 штук, а заказов
такого размера почти не бывает — это хорошая цена. Если она теряет с 1 штуки —
это не середина, это убыток.

### 3.4. Зона EU: одна цена на всех

«Другие страны Европы» — **одна строка** в панели на два десятка стран, а
посылка в Грецию стоит вчетверо против польской. Таблица показывает по каждому
весу самую дешёвую и самую дорогую страну и разброс между ними.

Цена зоны обязана покрывать **самую дорогую** страну — иначе каждый заказ туда
оплачивается из кармана. Инструмент называет эту страну и её цену.

Если разброс велик, у зоны есть три выхода, и все три — решение Рената:
поставить цену по самой дорогой стране (и переплачивают все остальные), вынести
дорогие страны в отдельные строки (в панели есть цена по конкретной стране, она
старше зоны), или выключить их в «Настройки → Доставка».

### 3.5. Насколько ответ зависит от догадки о весе

Одна строка на страну: во сколько обходится самый лёгкий заказ, во сколько
самый тяжёлый, и во сколько раз одно больше другого. Вывод справа:

- **«вес почти не влияет»** — можно не гадать, любая цена из таблицы годится;
- **«вес влияет заметно»** — держать запас, брать ближе к `без убытка`;
- **«вес решает всё»** — цена превращается в ставку на размер заказа, и стоит
  либо взвесить товар, либо брать `без убытка`.

### 3.6. Дыры и оговорки

Всё, что не сошлось: страны без цены, перевозчики без контракта, запросы,
которые не прошли, и страны, куда Montonio не возит вообще (сейчас это CH, CY,
GB, IS, LI, MT, NO).

**Ни одна строка здесь не означает «бесплатно».**

## 4. Дальше: куда вбивать числа

Админка → **Настройки → Доставка**, экран тарифов. Колонка «Пакомат» и колонка
«Курьер», строка на страну плюс «Другие страны Европы» и «Остальные страны».

Одна вещь, которую полезно знать заранее: **пустая клетка — это не ноль**. Она
означает «брать цену Montonio для этого перевозчика» (`quoteFromRules()` в
`src/lib/shipping.ts`). Так что если по какой-то стране решения нет, поле можно
просто оставить пустым, и магазин возьмёт цену из своей таблицы тарифов.
Набранное руками число всегда старше.

Панель, кроме того, не даст сохранить клетку ниже себестоимости — она сама
скажет, какую именно.

## 5. Чего этот инструмент не знает

Три вещи, и все три он говорит вслух, а не прячет.

### 5.1. Вес никто не мерил

В каталоге 220 товаров, и **ни у одного нет ни веса, ни габаритов** — в
`src/data/catalogue.min.json` лежат бренд, категория, id, название, цена и слаг,
и всё. Значит, узнать, в какую весовую полку попадёт настоящий заказ,
невозможно — это надо задать.

Инструмент не выдумывает число. Он берёт ту самую оценку, которая есть в коде, —
`estimateWeightKg()` в `src/lib/shipping/montonio.ts`: **0.4 кг на единицу товара
плюс 0.2 кг на коробку**. Вопрос задаётся в штуках (`--units N`), а не в
килограммах, потому что сколько банок в заказе — это Ренат знает, а «1.4 кг» — нет.

> Важно, с 19.09.2026: это вес **для расчёта тарифов**, а не тот, который магазин
> объявляет Montonio. На каждой посылке объявляется коробка —
> `declaredWeightKg()`, объёмный вес коробки из `settings.shipping_parcel`, одно
> и то же число при любом составе заказа. Решение Рената 18.09.2026: «вес заказа
> не считаем» (аудит 18.09.2026, F24). Раньше на посылке уходил именно
> `estimateWeightKg()`, и с трёх единиц платили за догадку, а не за коробку.

И раздел 3.5 честно говорит, насколько сильно ответ зависит от этой догадки в
каждой стране. Где зависит сильно — это первый кандидат на то, чтобы один раз
взвесить десяток типичных товаров и убрать неизвестное совсем.

То же самое с **коробкой**: её размеры тоже нигде не записаны, и полки в
инструменте растут вместе с заказом (20×15×10 см на одну единицу, 40×35×30 на
двадцать четыре). Это единственное, что здесь придумано, и придумано вслух —
а раздел 3.2 показывает, когда именно коробка начинает решать вместо веса.

### 5.2. Дыры в сетке — это дыры

Эндпоинт отвечает только про перевозчиков с контрактом Montonio. Пока контракты
неполные, часть сетки будет пустой, и **ни один расчёт не делает вид, что там
ноль**: зона не считает по стране без цены, средние не считают по дырам, а
итоговая маржа по такой стране просто не выводится.

Дыра почти всегда означает не «нет маршрута», а «не включён перевозчик». Это
чинится в partner.montonio.com за пять минут и меняет всю таблицу.

### 5.3. НДС: `rate` приходит без него — подтверждено 22.09.2026

Это надо знать, потому что все цифры здесь зависят от ответа на 24 %.

Про соседний эндпоинт известно было сразу: контрактные цены
(`contract-prices`) — **без НДС**, калькулятор Montonio так и пишет «+VAT», и
таблица тарифов магазина хранит их с добавленными 24 %, чтобы сравнивать с
витриной, где НДС тоже внутри.

Про `POST /shipping-methods/rates` в документации по-прежнему **не сказано
ничего**: в ответе есть `code`, `rate`, `currency` — и никакого поля про налог.
Поэтому спросили Montonio напрямую, и 22.09.2026 она ответила: `rate` — тоже
**без НДС**, как `pricePerParcel`.

С этого дня 24 % добавляют все, кто такое число сохраняет или сравнивает: обе
ветки `tools/fetch-montonio-tariffs.mjs` (контрактная цена и живой курс этого
магазина — проверено `tests/tariff-vat.test.ts`), `fetchMontonioRates()` в
`src/lib/shipping/montonio.ts` — там живой тариф иначе оказывался на четверть
ниже статической строки, которую он собой заменяет, — и этот инструмент. Он
пишет об этом на каждом экране и в каждом файле, который создаёт.

Флаг `--rates-include-vat` остался ручным переключателем на случай, если
Montonio однажды начнёт отвечать иначе. Это уже не открытый вопрос, который
ждёт первого счёта.

## 6. Почему без ключей он просто останавливается

Это не строгость ради строгости, а исправление конкретной ошибки.

Сегодняшняя таблица цен собрана скриптом `tools/fetch-montonio-tariffs.mjs`
через `contract-prices` — эндпоинт, которого **нет в документации** и который
не требует авторизации (`docs/montonio-shipping-audit.md` § 3.1). Он отдаёт
одну цену на `pickupPoint`, а у Montonio там три разных тарифа. Числа получаются
правдоподобные — и могут быть ценой пункта выдачи, выставленной за пакомат.
Покупатель этой ошибки не увидит никогда: она целиком вычитается из маржи.

Инструмент, который при отсутствии ключей тихо сходил бы на тот же эндпоинт,
воспроизвёл бы ровно ту ошибку, ради исправления которой написан. Поэтому
запасного пути нет:

| Что случилось | Код | Что делать |
| --- | --- | --- |
| нет ключей | `2` | выпустить ключи в partner.montonio.com |
| Montonio вернул 401/403 | `3` | **дело в ключах, не в перевозчиках**: проверить, что это ключи раздела Shipping, а не Orders, и что `MONTONIO_ENV` совпадает с тем, для чего они выпущены |
| Montonio вернул 429 | `3` | ограничение частоты — спрашивать меньше стран за раз через `--countries` |
| запросы вообще не прошли | `3` | это сеть, а не настройки — проверить доступ к хосту Montonio |
| Montonio ответил и не назвал ни одной цены | `3` | **вот теперь** идти включать перевозчиков |
| ошибка в самом скрипте | `1` | читать трассировку |
| всё хорошо | `0` | читать отчёт |

Три разные причины пустой сетки специально разведены: они отправляют к трём
разным экранам, и уверенная неправильная подсказка в воскресенье утром стоит
дороже, чем никакой.

`--dry-run` — это не запасной путь. Он читает
`tools/lib/delivery-pricing.sample.json` — **выдуманные** числа в настоящей,
документированной форме ответа Montonio, — и штампует «ОБРАЗЕЦ» на каждом
экране и в каждой строке записанного файла. Он существует, чтобы проверить сам
инструмент до того, как появились ключи, и годится ровно на это.

## 7. Где что лежит

| Файл | Что в нём |
| --- | --- |
| `tools/delivery-pricing.mjs` | запуск: ключи, запросы, печать, запись отчёта |
| `tools/lib/delivery-pricing.mjs` | вся арифметика, без сети и без файлов |
| `tools/lib/delivery-pricing.sample.json` | образец ответа для `--dry-run` и тестов |
| `tests/delivery-pricing.test.ts` | проверки; фикстуры списаны с документации Montonio, а не с наших ожиданий |
| `docs/montonio-shipping-audit.md` | сверка всей обвязки Montonio с документацией |
| `docs/shipping.md` § «Тарифы Montonio» | откуда взялась сегодняшняя таблица цен |
| `src/lib/shipping/country-prices.ts` | `costBasis()` — правило «чью цену покрывать» |
| `src/lib/shipping.ts` | `quoteFromRules()` — как цена доходит до счёта |

Соседний скрипт `tools/fetch-montonio-tariffs.mjs` никуда не девается: он по-
прежнему обновляет `src/data/montonio-tariffs.json`, из которого магазин
считает. Этот инструмент ничего не переписывает — он только показывает и
считает. Решение вбивается руками, и это сделано нарочно.
