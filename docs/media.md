# Фотографии — загрузка из админки, хранилище Cloudflare R2

Владелец фотографирует товар на телефон и загружает снимок прямо в админке.
Сервер сам поворачивает фотографию, вырезает из неё все лишние данные (включая
GPS-координаты, которые телефон кладёт в каждый снимок), уменьшает и переводит
в лёгкий формат WebP, а потом кладёт в бакет Cloudflare R2. В магазине
появляется ссылка на этот бакет.

Пока хранилище не настроено, кнопка «Загрузить фото» неактивна и под ней стоит
одна строка объяснения. Всё остальное в магазине и в админке работает как
работало — ни одна страница без R2 не ломается.

Файлы: `src/lib/storage.ts` (клиент R2), `src/lib/images.ts` (обработка
sharp), `src/app/api/admin/upload/route.ts` (роут),
`db/migrations/003_product_gallery.sql` (колонка `gallery`),
блок «Фото» в `public/shop2/app.js` (`galBlock()` и соседние функции).

---

## 1. Что делает Дмитрий один раз

### Бакет

1. Cloudflare → **R2 Object Storage** → **Create bucket**.
2. Имя `rempire-media`. Location: **EU** (юрисдикция ЕС — данные не уезжают из
   Европы; выбирается при создании и потом не меняется).
3. Storage class — Standard.

Бесплатный тариф R2: 10 ГБ хранения, 1 млн операций записи и 10 млн операций
чтения в месяц, **исходящий трафик бесплатный всегда**. Все фотографии магазина
— это несколько сотен мегабайт, так что счёт остаётся нулевым.

### Публичный адрес

Бакет по умолчанию закрыт; чтобы браузер покупателя видел картинки, нужен один
из двух публичных адресов:

* **Свой поддомен (рекомендуется).** Bucket → **Settings** → **Public access** →
  **Custom domains** → Connect domain → `media.rempireshop.com`. Домен должен
  быть в Cloudflare — то есть это делается **после** переноса NS с Zone.ee
  (см. `docs/accounts.md`, строка Cloudflare). Cloudflare сам добавит CNAME и
  выпустит сертификат.
* **Временный адрес r2.dev.** Bucket → Settings → Public access → **Allow
  Access** у `r2.dev subdomain`. Получится `https://pub-<хэш>.r2.dev`. Годится
  для проверки; для боевого магазина хуже — адрес некрасивый, лимитируется
  Cloudflare и его нельзя закэшировать своими правилами.

Адрес, который получился, целиком (со схемой, без слэша на конце) идёт в
`R2_PUBLIC_BASE`.

### Токен доступа

R2 → **API** → **Manage API tokens** → **Create API token**:

* Permissions: **Object Read & Write** (не Admin — этому магазину не нужно
  создавать и удалять бакеты).
* Specify bucket: только `rempire-media`.
* TTL: бессрочный.

Cloudflare покажет **Access Key ID** и **Secret Access Key** — второй только
один раз. Оба сразу в общий Bitwarden и в переменные окружения. `Account ID`
виден там же (и в адресе `https://<account-id>.r2.cloudflarestorage.com`).

## 2. Переменные окружения

Значения в этом файле не пишутся никогда — только имена.

| Имя | Что без него не работает |
| --- | --- |
| `R2_ACCOUNT_ID` | Идентификатор аккаунта Cloudflare — часть адреса API. |
| `R2_ACCESS_KEY_ID` | Ключ токена «Object Read & Write». |
| `R2_SECRET_ACCESS_KEY` | Секрет того же токена. Показывается один раз. |
| `R2_BUCKET` | Имя бакета, `rempire-media`. |
| `R2_PUBLIC_BASE` | Публичный адрес бакета: `https://media.rempireshop.com` или `https://pub-….r2.dev`. Слэш на конце не нужен — он всё равно срежется. |

Нет хотя бы одной — `storageConfigured()` возвращает `false`, роут отвечает
`503 storage_not_configured`, админка пишет «Загрузка фото пока не настроена».
Ставятся эти пять там же, где остальные (Vercel → Settings → Environment
Variables, Production + Preview; локально — `.env.local`).

## 3. Что происходит с фотографией

`POST /api/admin/upload/`, `multipart/form-data`, только для вошедшего
владельца (кука `rmp_admin`).

| Поле | Значение |
| --- | --- |
| `file` | Сам файл. |
| `kind` | `product` · `hero` · `review`. |
| `productId` | Обязательно при `kind=product`. |
| `reviewId` | Обязательно при `kind=review`. |

Ответ: `{ ok, url, thumbUrl, key, width, height, bytes }`.

Шаги на сервере, по порядку:

1. **Тип читается из первых байтов файла**, а не из имени и не из заголовка,
   который прислал браузер. Принимаются JPEG, PNG, WebP и AVIF.
2. **HEIC отклоняется отдельным сообщением** (`heic_unsupported`). Это формат,
   в котором айфон снимает по умолчанию; готовые сборки sharp собраны без
   HEVC-декодера (патенты), поэтому прочитать такой файл нельзя нигде — ни на
   Vercel, ни на Railway. Владельцу в админке пишется, что делать: «Настройки →
   Камера → Форматы → Наиболее совместимый», после чего айфон снимает в JPEG.
   На практике этот путь редкий: Safari при выборе снимка из плёнки в форму
   сам отдаёт JPEG.
3. **Больше 12 МБ — отказ** (`too_large`) ещё до чтения файла в память.
4. Поворот по EXIF, чтобы снимок «боком» встал прямо.
5. **Все метаданные срезаются** — EXIF, GPS, ICC, XMP.
6. Уменьшение до 1600 px по длинной стороне (меньшие не увеличиваются) и
   кодирование в WebP, качество 82. Прозрачность сохраняется, если она была:
   фотографии товаров на этом сайте — вырезанные объекты без фона.
7. Отдельно делается миниатюра 400 px — тот же ключ с суффиксом `-thumb.webp`.
   Её показывает админка в списке фотографий.
8. Оба файла кладутся в бакет и записываются в журнал изменений (`admin_audit`,
   действия `media.upload` и `media.delete`).

Ограничение: **60 загрузок в час** на один вход в админку.

### Имена файлов в бакете

```
products/<id товара>/<метка времени>-<имя>.webp
products/<id товара>/<метка времени>-<имя>-thumb.webp
hero/<метка времени>-<имя>.webp
reviews/<id отзыва>/<метка времени>-<имя>.webp
```

Метка времени в имени — это то, что делает замену фотографии новым адресом:
ни один кэш (браузера, Cloudflare, письма) не нужно уговаривать забыть старую
картинку. Поэтому файлы отдаются с `Cache-Control: immutable` на год.

`DELETE /api/admin/upload/?key=…` удаляет объект вместе с его миниатюрой и
принимает только ключи с этими тремя префиксами — ничего другого из бакета
удалить нельзя. Админка вызывает его лишь для фотографии, загруженной в этот же
заход и убранной до сохранения: всё, что уже сохранено, из бакета не пропадает,
иначе «Отменить» в журнале вернуло бы ссылку на несуществующий файл.

## 4. Где фотографии оказываются в магазине

Список фотографий товара лежит в `product_overrides.gallery` (jsonb, миграция
`003_product_gallery.sql`):

```json
[{ "url": "https://media.rempireshop.com/products/touchable/1756900000000-a.webp",
   "thumb": "https://media.rempireshop.com/products/touchable/1756900000000-a-thumb.webp",
   "alt": "" }]
```

Пустое значение (`null`) означает «фотографии из каталога» — те, что лежат в
`public/shop/img` и генерируются инструментами. Непустое **заменяет** их
целиком; первая в списке — главная, она стоит на карточке, в поиске и в
письмах.

Отдаётся оно вместе с остальными правками:

* `GET /api/overrides/` (публичный, кэш 30 с) → `overrides.<id>.gallery`;
* `PUT /api/admin/overrides/ { id, gallery: [...] }` — сохранение;
* в витрине это `DEMO.gallery[id]`, из которого `applyDemoOverrides()` делает
  `p.gallery` и `p.img`, а `gal(p)` уже читают карточка, страница товара и
  баннер.

**Связь с «Фото по объёмам».** Существующая правка `varImg` — это номера
позиций в списке фотографий («75 мл показывать вторую»). Когда список меняется,
номера, вышедшие за его конец, автоматически указывают на главную фотографию:
и в редакторе (`goodsEditor()`), и в витрине (`applyDemoOverrides()`), и на
сервере ничего не ломается.

Картинка баннера (`kind=hero`) в базу так не попадает: она подставляется
ссылкой в поле «Картинка» слайда и уезжает в `settings.hero` вместе с ним —
см. `docs/features.md`, «Главный баннер».

## 5. Админка

**Товары → Править → блок «Фото».** Плитки текущих фотографий, у каждой ↑ ↓,
«Сделать главным» и «Удалить»; кнопка «Загрузить фото» (на телефоне открывает
камеру или плёнку, на компьютере — обычный выбор файла, и туда же можно
перетащить файлы мышью); можно выбрать сразу несколько — они загружаются по
очереди, кнопка показывает «Загружаем… 2 из 5». Ничего не применяется само:
пока не нажата «Сохранить», это черновик, а «Отмена» его выбрасывает.
«Вернуть фото из каталога» стирает правку целиком.

Сохранение попадает в журнал изменений в «Настройках» и отменяется оттуда одной
кнопкой, как цена или наличие (действие `set_gallery`).

**Настройки → Главный баннер → Изменить → «Загрузить свою картинку»** — тот же
механизм, ответом заполняется поле со ссылкой на картинку слайда.

Все строки блока переведены на эстонский и английский в словаре `UI` в
`app.js`.

## 6. Проверка после того, как бакет создан

```bash
# 1. пять переменных в .env.local, затем
npm run dev
# 2. открыть /shop2/admin/, войти, Товары → любой товар → «Фото»
#    — кнопка активна, значит GET /api/admin/upload/ вернул configured:true
# 3. загрузить снимок с телефона; ожидаем: плитка появилась, в бакете два
#    файла (…​.webp и …-thumb.webp), в «Настройках» строка в журнале
# 4. «Сохранить» → открыть товар в магазине: новая фотография на карточке
# 5. Отменить в журнале → вернулись прежние фотографии
```

Проверить сам подписанный запрос без загрузки картинки нельзя — R2 отвечает на
неверную подпись `403 SignatureDoesNotMatch` без объяснений. Поэтому
арифметика подписи (SigV4) проверяется тестом против опубликованного примера
AWS: `tests/storage.test.ts`.

## 7. Мелочи, о которых стоит помнить

* **`sharp` — нативный модуль.** Он в `dependencies`, версия закреплена
  (`0.35.3`), и в `package-lock.json` лежат бинарники для linux-x64,
  linux-arm64 и musl, иначе сборка на сервере с `npm ci` встанет на «Could not
  load the sharp module». Vercel и Railway такую сборку тянут штатно.
* **Лимит тела запроса.** Serverless-функция Vercel принимает не больше 4,5 МБ
  в запросе, поэтому на staging снимок с хорошего телефона может не пройти,
  хотя код разрешает 12 МБ. На Railway (боевой хостинг, см. `docs/accounts.md`)
  такого потолка нет.
* **Фон не снимается автоматически.** Загруженная фотография уменьшается и
  сжимается, но вырезать объект из фона по-прежнему нужно заранее — этим
  занимаются инструменты в `tools/`.
* **Отзывы.** `kind=review` уже принимается роутом и складывает файлы в
  `reviews/<id>/…`; интерфейса для фотографий в отзывах пока нет.
