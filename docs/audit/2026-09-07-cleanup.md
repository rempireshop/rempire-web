### What that removes from the attack surface

1. **`'unsafe-eval'` no longer exists anywhere in the CSP.** It was granted to
   `/prototypes/:path*` because those pages compiled their own JSX at run time
   — the single most dangerous directive in the policy, on a path that took
   uploads (`public/prototypes/uploads/`) and ran a vendored Babel.
   `tests/security-product-page.test.ts` now asserts that **no** header rule
   carries `unsafe-eval`, `unsafe-hashes` or `strict-dynamic`, so it cannot
   come back by accident.
2. **Two unauthenticated POST endpoints are gone.** Both wrote to a Vercel Blob
   store, both forwarded their body to a Telegram chat and to an e-mail
   address, and neither had a rate limit or a session. They were the only
   readers of `@vercel/blob` and the only reason the Blob store on Diip's team
   still mattered (see question 3).
3. **The site root is no longer a redirect to a review hub** — a stranger
   typing the domain landed on internal design work with the owner's video
   messages on it.
4. **~11.7 MB of assets left the deployment**, including four owner videos and
   a copy of the licensed `KorolevBold.otf` under `public/prototypes/public/`
   (the real one stays in `public/fonts/`).
5. **One React attack surface fewer.** With no page in the app router, Next
   renders no HTML of its own at all — every response is a route handler or a
   static file.

### TLS to the database (Appendix B 23, security audit M9) — fixed, needs watching

`sslFor()` used to turn certificate verification **off** for any
`DATABASE_URL` whose host ended `.rlwy.net` or `.railway.app`. Two things were
wrong with that: a security decision lived in a substring of a connection
string, where no review of the environment variables could see it; and
renaming the database host silently changed whether the shop checked who it
was talking to.

Now the decision is in the environment, in `src/lib/db.ts` and
`tools/migrate.mjs` alike, and `tests/migrations.test.ts` pins the two to the
same answer so the build cannot use a looser rule than the app:

| | |
|---|---|
| local host, or `?sslmode=disable` | no TLS |
| `DATABASE_SSL_NO_VERIFY=1` | TLS, certificate **not** checked |
| `DATABASE_SSL_CA=<PEM>` | TLS, certificate checked **against that CA** |
| otherwise | TLS, certificate checked against Node's public trust store |

**`DATABASE_SSL_CA` is new, and it is why this is a security improvement
rather than a relocated switch.** Railway's Postgres image "creates a private
Certificate Authority (CA) and a CA-signed server certificate" on first
startup ([railway.com/deploy/postgresql--postgresql](https://railway.com/deploy/postgresql--postgresql)),
so the public trust store genuinely cannot verify it — removing the exemption
without an alternative would have left "turn verification off" as the only
way to deploy, which is where we started. Railway documents an export
(`railway ssh … -- export-ssl-ca`); paste the result into `DATABASE_SSL_CA`
and the connection is authenticated for the first time. It is a public
certificate, safe in an environment variable; the private keys stay in the
database.

`src/lib/db.ts` also says which of the three states it is in, once per
instance, in the log — and the "checked against the public store on a provider
that signs its own" line names both variables, so a failed connection explains
its own fix. No line prints the URL. Documented in `docs/backend.md` ("TLS to
the database") and in the `docs/accounts.md` variable table.

**This is the one change here that can break a deploy** — see question 8.

### `RESEND_TO` (Appendix B 10) — fixed

`src/lib/notify.ts` defaulted the owner's "new order" ping to
`info@diipsolutions.eu` — Dim's own address — sent from Resend's
`onboarding@resend.dev`. A production shop that nobody had finished configuring
therefore mailed a third party the customer's name, e-mail, address and basket
on every paid order, and looked configured while doing it.

There is no default any more. With `RESEND_TO` unset the ping is not sent and
the log says so, naming the variable and the intended value. The sender
fallback is now the shop's own verified `Rempire <shop@rempireshop.com>`, the
same one customer mail uses, instead of Resend's onboarding address. Four tests
in `tests/mail-hooks.test.ts` pin it, including "never mails an address the
code chose". The customer's own letter is unaffected — that goes to the
address on the order and always did.

Dim's answer: the owner's alerts go to **shop@rempireshop.com**. That is now
in `docs/accounts.md`. See question 9.
