# Rempire — the barcode scanner and the stock/product binding flow

Audit **and** fix pass, 06.09.2026, branch `r-scanner` (based on `1a63cf8`).
Scope: everything between a barcode on a bottle and a number in `stock_levels` —
the camera, the «К какому товару?» binding card, the «Склад» list and ledger, and
the «Штрихкод» column of the product editor.

Written against Dim's report from the owner's phone (Samsung Galaxy S21 FE, Android):

> "Scanning was hard and almost impossible. Also it seemed to be impossible for
> existing products to scan the code. All related to scanning and product
> management needs big improvements."

and, earlier:

> "keyboard jumps out too often when scanning", "I have scanned 300ml Awapuhi
> shampoo, nothing got added, size was not able to select".

Nine commits, all on `r-scanner`, nothing pushed. Every bug below was reproduced
first (in a test or by reading the state machine), then fixed, then pinned by a
test that fails without the fix.

**The one fact that shapes everything here:** the catalogue has **no barcodes**.
Verified in this tree: `public/shop/catalogue2.js` has no EAN field and contains
no 12–14 digit string anywhere (the only `ean` matches in it are inside
«cleanser»/«cleansing»). An earlier pass over the Shopify export found its
`Variant Barcode` column set to `NA` on all 356 filled rows — that export is not
in the repo, so that half is second-hand; the catalogue half is not.
There is no import to do. The only way a code ever reaches the database is the
owner scanning a bottle and tapping a product, so that one path has to be
bulletproof. Renat confirmed the stock has them (`docs/RENAT-ANSWERS.md` row 3,
«Да, почти у всех товаров»).

## 1. The system map

### Screens and their code

| Surface | Where | What it is |
|---|---|---|
| Standalone scanner app | `/shop2/scan/` → `screenScan()`, `scanRouteSync()` in `public/shop2/app.js` | Third home-screen icon (`public/shop2/scanner.webmanifest`), admin-gated exactly like `/shop2/admin/`. Always in warehouse mode. |
| Scanner overlay | `scanMount()` / `scannerShellHTML()` / `scanPanelHTML()`, `SCANEL` | The *same* screen raised over «Склад» (`data-scanopen`) or «Салон». Mounted **outside** `bodySlot` on purpose: a `<video>` inside the `render()`-driven `innerHTML` loses its stream on every unrelated state change. |
| «Склад» | `admStockHTML()`, `stockRows()`, `stockRowHTML()`, `stockEditFormHTML()` | The list, the ± stepper, the per-row form (EAN · «Порог «мало»» · «Остаток сейчас» · «Причина»). |
| «Склад» → history | `admStockMovesHTML()`, `loadStockMoves()` | The ledger, filtered by reason. |
| «Товар» → «Размеры и цены» | `edPaneSizes()` / `edPaneSizesOwn()`, `edEanCell()`, `edEanHint()` | The per-size grid: `Размер · Цена · Салон · Остаток · Штрихкод · ×`. «Остаток» and «Штрихкод» here are the **warehouse**, not overrides. |

### Routes

| Route | Methods | Used by |
|---|---|---|
| `/api/admin/inventory/` | `GET` (list, `?filter=all\|low\|out&q=`), `PUT` (bind/unbind an EAN, set `lowThreshold`) | «Склад», the editor grid, the binding card, `unbind()` in the e2e spec |
| `/api/admin/inventory/lookup/` | `GET ?ean=` | Every camera hit, every manual code, every handheld-scanner burst |
| `/api/admin/inventory/moves/` | `GET` (ledger), `POST` (a relative or absolute qty change) | ± stepper, «Приход +N» / «Списание −N», «Остаток сейчас», «Сегодня» on the scanner card |

Server rules live in `src/lib/inventory.ts` (`setLevel`, `move`, `byEan`,
`deriveState`, `normEan`); the HTTP wrappers add auth and the `takenBy` detail.

### Tables (`db/migrations/090_inventory.sql`)

- `stock_levels (product_id, variant, qty, low_threshold, ean, updated_at)`,
  primary key `(product_id, variant)`, plus a **partial unique index on `ean`
  where ean is not null** — this is what makes «этот код уже занят» a database
  guarantee and not a race.
- `stock_moves` — the ledger; `stock_levels.qty` is the sum of every delta ever
  applied. `variant` is the size **label** (`"40 мл"`), never an index.
- No new migration was needed for this work; number 143 stays free.

### Client state

`S.scan*` — `scanOpen`, `scanErr`, `scanHit`, `scanAssignQ`, `scanAssignPick`,
`scanBindConfirm`, `scanQty`, `scanBusy`, `scanReady`, `scanToday`, `scanTorchOk`,
`scanTorchOn`, `scanHint`, `scanFrom`, `scanApp`, `scanSupport`.
`S.stock*` — `stockLevels`, `stockBusy`, `stockErr`, `stockQ`, `stockFilter`,
`stockEdit`+`stockEdit{Qty,Reason,Ean,Low}`, `stockMoves`, `stockMovesBusy`,
`stockMovesErr`, `stockMovesReason`, `stockMovesOpen`.

Two non-`S` bookkeeping objects, both deliberate: `STOCK { asked, seq, movesAsked }`
(request de-duplication) and `SCAN { stream, engine, timer, video, panelKey,
assignFocused, wedge, pendingCode, nativeSince, nativeHit, nativeErrs,
nativeFormats, zxingLoad, zxingFailed, crop, full }` (the camera, which must not
be re-created by a render).

### The camera engine, after this pass

```
startScanEngine()
 ├─ zxing script fetched from second one (cached; a failed fetch is retried on the next open)
 ├─ BarcodeDetector.getSupportedFormats()   ← an empty list = skip the native path at once
 ├─ scanOpenCamera() → remembered lens, else facingMode:environment → scanPickLens()
 │     └─ enumerateDevices → back lenses → drop wide/ultra/tele/macro → lowest camera2 index
 │        → hand the stream over (never two streams at once) → remember in localStorage
 ├─ scanTuneTrack(): focusMode:continuous, zoom≈1.5×, torch re-checked at 0/0.5/1.5 s
 └─ startNativeLoop()  ── throws, or six mute seconds ──▶ scanNativeGaveUp() ──▶ startZxingLoop()
        every 120 ms, alternating full frame / centred crop drawn 2×
        a code counts on two consecutive agreeing reads → handleScanCode() → lookup
```

Ordered as they were landed. Every row's commit is on `r-scanner`.

### Deliberately **not** changed

- **The editor's «Штрихкод» cell is still typable.** The brief asked for read-only.
  `e2e/admin-editor.spec.ts:135` and `docs/design/admin-handoff-README.md:112` both
  pin it as an editable box, and removing it is a product decision, not a bug fix —
  see question 1 below. It now shows «Отвязать» and a real "not bound" state, which
  is what the complaint was actually about.
- **The flat «3 или меньше» in the *editor* grid** — its own hint says so in words
  («Остаток красный, когда его 3 или меньше»), and that screen has no threshold
  control. Only «Склад», which does, was changed. Question 3.
- **`scanSizeHas()`** in the scanner's own search is untouched; «Склад» got a
  sibling (`scanWordHas`) that also lets a partial barcode match, which the
  scanner's product search must not do.

## 4. How to test it on the S21 FE — a checklist for Dim

Do this in order. Steps 1–3 are the setup that decides whether the camera can
work at all; 4–8 are the actual flow.

1. **HTTPS, always.** `getUserMedia` is refused outside a secure context. The
   live domain is fine; a preview URL is fine; a `http://192.168.x.x` dev server
   is **not** — the camera will simply never start and the screen will say
   «Нет доступа к камере (NotAllowedError)». Test on the deployed URL.
2. **Open `https://rempireshop.com/shop2/scan/`** and sign in once. Optionally
   add it to the home screen (Chrome: ⋮ → «Установить приложение»); the icon is
   called «Сканер».
3. **Grant the camera when asked, and pick "While using the app"** — not "Only
   this time", which makes Android re-ask on every open.
   *To reset the permission later:* Chrome → tap the ⚙/🔒 icon left of the
   address bar → «Разрешения» → «Камера» → «Сбросить разрешения», then reload.
   Samsung Internet → 🔒 icon → «Разрешения» → «Камера».
   *If the site is installed as an app:* Android Settings → Apps → the «Сканер»
   entry (or Chrome) → Permissions → Camera.
4. **Watch which lens comes up.** The picture should look like the ordinary
   photo camera, not a wide-angle one — no curved edges, and text at 15 cm
   should be sharp. If the first open looks wide, close and open once more: the
   chosen lens is remembered from then on (`localStorage`, key `rmp-scan-camera`).
   Clearing site data resets that choice.
5. **A good scan looks like this.** Hold the bottle so the barcode fills roughly
   the middle third of the square viewfinder — about 10–20 cm away, code
   horizontal, phone steady for half a second. It beeps *and vibrates* on a hit,
   and the card appears. The code has to be read on two consecutive frames, so a
   quick wave past the label deliberately does not count.
6. **Test both browsers.** Chrome uses Android's own detector; **Samsung
   Internet has none**, so it uses the bundled zxing decoder — the same screen,
   a little slower. Both must find the same codes.
   If Chrome shows «Камера читает через запасной декодер — держите код ближе и
   ровнее» under the viewfinder, that is the automatic hand-over: this phone's
   Play Services barcode module is missing or broken. Not an error — but tell us,
   because it means Chrome and Samsung Internet are decoding identically there.
7. **Bind one code end to end.** Scan a bottle nobody has scanned before → the
   card says «Код не найден» and «К какому товару?» → type part of the name the
   way you would say it («murphy tangled 40» works; so does «300 ml») → tap the
   row with the right size → «Код привязан ✓». Scan the same bottle again: the
   product card appears with its remainder. Set the number and press «Приход +N».
   Close the scanner: the «Склад» row behind it must already show the new code
   and the new count, with no reload.
8. **When it fails.** In this order:
   - dirty or creased label → wipe it, flatten it, try again;
   - dark stockroom → press 🔦 in the scanner's top bar (it appears a second or
     two after the camera starts on some Samsungs);
   - still nothing after ~10 seconds → type the digits into «или введите код
     вручную» and press «Найти». This is a first-class path, not a workaround —
     everything after the code arrives is identical.
   - a bluetooth/USB handheld scanner also works: with the scanner screen open
     and nothing focused, just scan; its digits + Enter are picked up.
   **What to send us if it still fails:** which browser, whether the hint about
   the «запасной декодер» was on screen, whether the torch button appeared, and
   a photo of the barcode you were pointing at.

## 5. Questions for Dim

Numbered so they can be answered by number. None of these were decided in code.

1. **Should the editor's «Штрихкод» cell stay hand-typable?** The brief asked for
   read-only + «Отвязать». It was left typable because `e2e/admin-editor.spec.ts`
   and `docs/design/admin-handoff-README.md:112` both pin it as an editable box,
   and «Склад»'s own row form has a full-width EAN field for typing a code by
   hand. Making it read-only is a two-line change plus one test edit — say the
   word.
2. **Should «Отвязать» in the editor free the code immediately, or on «Сохранить»?**
   It currently empties the box and waits for «Сохранить» (so a mis-tap on a phone
   costs nothing), unlike «Отвязать код» in the scanner, which acts at once because
   it is a scanner decision. Two different behaviours for one word — acceptable, or
   should they match?
3. **What does a red remainder mean?** «Склад» now says "below this row's own
   «Порог «мало»»" (server default 2); the editor grid still says "3 or fewer" and
   its hint says so in words. Should the editor follow the per-row threshold too,
   and should the default stay 2 or become 3?
4. **Custom codes.** `normEan()` accepts 8–14 digits **or** a 4–32 character code
   of letters/digits/hyphens. Does Renat ever stick his own printed labels on
   things (sets, decanted product, salon-only items)? If yes we should say so in
   the UI; if no we should tighten the rule to digits only, which removes a class
   of misreads.
5. **The 1.5× zoom** is a fixed guess that suits a 100–300 ml bottle at arm's
   length. If Renat mostly scans large boxes on a shelf it is wrong. Worth a
   pinch-to-zoom control on the viewfinder, or leave it fixed?
6. **Two-frame confirmation** costs roughly 240 ms per scan and rejects a
   quick wave past a label. It is what stops a curved-label misread. Keep it, or
   trade the safety for speed once Renat has used it for a week?
7. **Nothing bulk-binds.** With no barcodes in the catalogue, the first pass over
   the shelves is one scan + one tap per bottle — roughly 220 products, more with
   sizes. Is there an evening where Renat does that in one go, and does he want a
   «прошло N из M» counter to work through it? (Not built; it is a product
   decision.)
8. **The scanner writes «приход»/«списание» with `ref: "сканер"`.** Should a
   goods-in from a supplier delivery carry the invoice number instead, so the
   ledger can be reconciled against a supplier bill? That touches the invoice
   agent's area, so it was not started.
9. **Should «Склад» keep capping the list at 60 rows?** With ~350 rows and no
   pagination, the tail is only reachable by searching. Fine for a phone, but
   worth knowing whether Renat ever scrolls a full list.
10. **The camera hint about the «запасной декодер»** is honest but technical for
    a non-technical owner. Keep it (it is the one signal that tells us the phone's
    Play Services are broken), soften the wording, or hide it and only log it?
