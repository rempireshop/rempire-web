# Build contracts (pre-access build wave, 03.09.2026)

Shared rules for parallel work in this repo. Six agents work in the same tree at once.

## Stack
- Next.js 15 App Router, TypeScript, **no ORM**. Storefront = vanilla JS SPA in `public/shop2/` (app.js IIFE, chat.js, styles.css, index.html; asset URLs carry `?v=` versions — bump the token in index.html when you change app.js/styles.css/chat.js). `chat.js` has no tag of its own in index.html: `mountChat()` in app.js adds it, wide screens only, and copies the token off the app.js tag — bumping index.html still covers it.
- Catalogue: `public/shop/catalogue2.js` (generated by `tools/build-catalogue-full.mjs`) and `src/data/catalogue.min.json` — never hand-edit generated files. Same rule for `src/data/content.default.json` (`tools/pack-content.mjs`, from `DEFAULT_CONTENT` in `src/lib/content.ts`) and `src/db/migrations.generated.ts` (`tools/pack-migrations.mjs`); both run in `prebuild`.
- DB: Postgres, `DATABASE_URL`. Client `pg`. Migrations = plain SQL in `db/migrations/NNN_name.sql`, applied by `tools/migrate.mjs` (`npm run migrate`, tracked in `_migrations`). Tests run migrations on `@electric-sql/pglite` (in-memory) via `DB_DRIVER=pglite`.
- Migration number ranges: backend-core 001–009 · features 020–029 · checkout/payments/shipping 030–039 · mail 040–049 · account-flows 050–059 · checkout-gaps 060–069 · blog 070–079 · analytics 080–089 · inventory 090–099 · loyalty 100–109 · assistant helpers 110–119. Never edit another range.

## Shared modules (owner: backend-core; others import, don't edit)
- `src/lib/db.ts`: `query<T>(sql: string, params?: unknown[]): Promise<T[]>`, `withTx<T>(fn: (q) => Promise<T>)`.
- `src/lib/auth.ts`: `requireAdmin(req: Request): Promise<Response | null>` → 401 JSON Response when not admin, otherwise null. Cookie `rmp_admin`, HMAC with `SESSION_SECRET`.
- `src/lib/orders.ts`: `createOrder(input)`, `getOrder(id)`, `getOrderByNumber(n)`, `setOrderPayment(id, payment)`, `setOrderStatus(id, status, actor)`. Order shape = `db/migrations/001_core.sql` `orders` table (items jsonb, shipping jsonb, payment jsonb, totals numeric, `number` like `R-100042`).
- If a shared module is missing when you need it: poll for it (every 2 min, up to 20 min). Only if still missing, create a minimal stub with exactly these signatures (Write only when the file does not exist).

## API conventions
- Routes in `src/app/api/<area>/route.ts`. JSON `{ ok: true, ... }` / `{ ok: false, error: "code" }`. Manual validation, no new validation libs. Public routes rate-limited per IP (in-memory map is fine).
- Env names (document in docs/, never commit values): DATABASE_URL, SESSION_SECRET, ADMIN_PASSWORD_HASH, RESEND_API_KEY, RESEND_FROM, MAIL_REPLY_TO, PAYMENT_PROVIDER, MONTONIO_ACCESS_KEY, MONTONIO_SECRET_KEY, MONTONIO_ENV, OPENAI_API_KEY, PUBLIC_BASE_URL.

## Concurrency rules
- Existing files: **Edit only** (string replace), re-read the region right before editing, small hunks, no reformatting, no Write on files that exist.
- Stay inside your owned files/regions. app.js regions are named in each brief.
- No `git commit`, `git push`, deploys. Do not bump package versions of existing deps. `npm install` for new deps is fine.
- Trilingual: every customer-facing string goes through the UI dictionary in app.js (RU key → { ET, EN }).
- Finish with `npm run typecheck` + your tests; report changed files and how to verify.
